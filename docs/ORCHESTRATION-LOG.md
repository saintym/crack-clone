### 측정: CLI 프롬프트 크기·캐시 (2026-09-24)
사용자 질문("에이전트가 계속 떠 있는데 왜 매 턴 전체를 보내야 하나")에서 시작해 `claude -p`에 직접 프롬프트를 넣어 쟀다.
- **프롬프트 크기와 지연은 무관하다.** 3,055자 / 30,055자 / 85,041자에서 첫 토큰까지 3.2~5.8초, 전체 6.0~8.5초로 차이가 없었다. 지연은 **출력 길이**가 좌우한다.
- **CLI는 이미 프롬프트 캐싱을 하고, 프로세스가 달라도 접두사가 같으면 캐시를 읽는다.** 같은 60,000자 프롬프트를 새 프로세스로 두 번 호출하니 2회차는 캐시 쓰기 0, 캐시 읽기 42,856토큰, 비용 $0.2565 → **$0.0161(16배)**. 세션 ID는 서로 달랐다.
- **결론(D29):** 세션 유지(`--input-format stream-json`, `--resume`)는 구현하지 않는다. 얻을 이득이 실측상 없고, 오래된 원문 정리·수정·삭제·분기가 깨진다.
- **새 발견(D30):** 캐시는 접두사 일치라서 **활성 인물이 매 턴 바뀌면 캐시가 깨진다.** 활성 인물 집합을 기억 기록 회차 동안 고정하도록 T24 명세에 추가했다.
- **교훈:** "프롬프트를 줄여야 한다"는 직관의 근거가 바뀌었다. 지연이 아니라 ① 출력 품질 ② 접두사 안정성 ③ API 전환 시 비용이다. 측정 없이 최적화 대상을 정하면 엉뚱한 곳을 고친다.
