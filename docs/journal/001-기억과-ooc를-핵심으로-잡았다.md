## 무슨 일이 있었나
v1은 Phase 3까지 만들고 멈춰 있었다. 다시 시작하려고 원작(크랙)의 대화 관련 기능을 조사했다. 공식 공지 약 317건과 고객센터, 커뮤니티 자료를 훑고, 우리 코드도 따로 읽어 기능별로 대조했다. 그 결과 스무 개 넘는 격차가 나왔다. 전부 만들 수는 없어서 **기억력과 OOC 지시 유지** 두 개를 핵심으로 잡았다.

## 왜 이걸 하고 있었나
개인용 취미 앱이자 포트폴리오다. "원작에 있는 걸 다 넣었다"는 결과물은 포트폴리오로도 약하다. 무엇을 **왜** 골랐는지가 남아야 한다.

## 조사에서 나온 것
- 원작은 요약 메모리를 4영역(단기·장기·관계도·목표)으로 나누고, 장기 기억은 사용자가 최대 100개까지 직접 고칠 수 있다.
- 유저노트는 500자 무료, 2000자로 늘리면 메시지당 과금이다.
- 커뮤니티에서 반복되는 불만이 두 개였다. **50~100턴 지나면 설정이 어긋난다**, **OOC 지시가 20턴쯤 뒤 잊힌다**. 기억력을 보완하는 서드파티 스크립트까지 돌아다녔다.
- 우리 v1은 10턴마다 파일 요약 하나가 전부였고, 그마저 기본 설정에서는 조용히 실패하고 있었다(API 키가 없으면 요약 호출이 죽었다).

## 결정
| 넣기로 한 것 | 이유 |
|---|---|
| 기억 3계층(인물 문서·주인공 문서·연대기) | 원작의 4탭을 베끼지 않고, 사용자가 직접 읽고 고칠 수 있는 마크다운으로 간다 |
| 지속 OOC 지시 | 원작에서 20턴 뒤 잊히는 문제. 해제할 때까지 프롬프트 맨 아래에 넣는다 |

| 버린 것 | 이유 |
|---|---|
| 턴별 모델 선택 | 개인용이라 프로바이더(CLI/API) 선택으로 충분하다 |
| 파티챗, 엔딩, 실시간 스탯, 이미지 생성 | 혼자 쓰는 앱에서 값이 낮다 |
| 크래커·성인인증·공유 허브 | 상용 요소다 |

## 왜 이 방법을 골랐나
- 원작의 강점을 베끼는 대신 **원작 사용자들이 불만을 말한 지점**을 골랐다. 클론이 원작을 이길 수 있는 곳은 거기뿐이다.
- 버린 목록을 문서에 남겼다. 나중에 "왜 이건 없냐"는 질문에 답이 된다.
