## 무슨 일이 있었나
v1은 매 턴 시나리오의 인물 문서를 **전부** 프롬프트에 넣었다(마도생존기 기준 24명, 140KB). v2에서 "동행 인물 + 최근 대화에 이름이 나온 인물"만 넣도록 바꿔 시스템 프롬프트를 192KB → 56~79KB로 줄였다. 그런데 실제 데이터로 섹션별 크기를 재 보니, 남은 것 중 `scenario.md` 하나가 17,698자로 **전체의 62%**였다.

## 측정
마도생존기 실데이터, `prompt-preview`로 섹션별 글자 수(UTF-16 길이).

| 섹션 | 글자 수 |
|---|---|
| base(기본 규칙+출력 형식) | 1,128 |
| world | 3,653 |
| **scenario** | **17,698** |
| protagonist | 2,315 |
| characters (1명) | 3,524 |
| characters (4명) | 11,957 |
| user_note | 19 |

v1 대비: 인물 언급 0명일 때 192,013 B → 56,220 B(−71%), 3명 매칭일 때 79,303 B(−59%).

## 결정
사용자가 제안한 "여러 관리자" 구조를 여기에 붙였다. 핵심은 **세계관 관리자가 원문을 한 번만 읽는다**는 것이다.

1. 스토리를 시작할 때 1회: `scenario.md`를 읽어 ① 다이제스트(항상 주입, 3,000자 예산) ② **색인된 조각**(주제 단위 + 키워드)을 만든다. 색인 형식은 키워드북과 같게 해서 기존 매칭 엔진을 재사용한다.
2. 그 뒤로는 원문을 다시 읽지 않는다. 관리자 일은 연대기에 사건을 덧붙이는 것과, 연대기를 압축할 때 다이제스트를 갱신하는 것뿐이다.
3. 과거 정보가 필요하면 **관리자에게 묻지 않고 검색으로 주입한다.** LLM 호출 0회, 대기 0초.
4. 검색이 아무것도 못 찾았고 과거를 참조하는 신호가 있는 턴에만, 관리자를 1회 자동 호출한다.

## 버린 대안
| 대안 | 버린 이유 |
|---|---|
| 원문을 그대로 두기 | 62%를 계속 낸다 |
| 다이제스트만 넣고 원문은 완전히 버리기 | 다이제스트가 놓친 세부 설정을 AI가 영영 못 본다 |
| 매 턴 관리자에게 질의 | 턴마다 10~20초가 더 걸린다. "응답 전에는 LLM을 부르지 않는다"는 원칙과 정면으로 어긋난다 |

## 같이 정한 것: 대화 원문 범위
사용자가 "최근 20턴을 들고 플레이"를 제안해서 실제 메시지 길이를 쟀다.

| 항목 | 측정값 |
|---|---|
| AI 응답 1건 | 평균 929자 (76~2,282자) |
| 유저 메시지 1건 | 평균 33자 |
| 한 턴 | 약 960자 (검증 스토리) / 약 1,900자 (실제 데이터) |

20턴이면 2만~3만 8천 자다. 시스템 프롬프트 전체와 맞먹는다. 다이제스트로 아낀 1만 5천 자를 그대로 상쇄하고 더 넘긴다. 그래서 **턴 수가 아니라 글자 예산**으로 바꿨다. 기본 6,000자, 상한 10,000자, 최소 2턴 보장. 응답 길이 편차가 30배라 턴 수 기준은 예측이 되지 않는다.
