## 무슨 일이 있었나
프론트 작업을 여럿 끝내고 빌드·린트를 모두 통과시켰다. 기억 패널을 만들면서 처음으로 헤드리스 Chromium을 띄워 실제 화면을 찍었다. 말풍선·버튼·패널의 여백이 **전부 0**이었다. 앱 전체에 걸친 문제였고, 처음부터 그랬다.

## 증상 / 막힌 지점
- 재현 조건: 아무 화면이나. `p-*`, `m-*` 클래스가 붙은 요소의 실제 padding이 0
- 원인이 된 CSS:
```css
/* index.css, 레이어 밖 */
* { margin: 0; padding: 0; }
```
- 처음에 의심한 것: 내가 방금 만든 패널의 클래스 이름을 잘못 썼다고 봤다.

## 원인
- 진짜 원인: CSS cascade layer에서 **레이어 밖 규칙이 레이어 안 규칙을 이긴다.** Tailwind v4 유틸리티는 `@layer utilities` 안에 있어서, 레이어 밖의 전역 리셋에 밀렸다.
- 확인한 근거: 리셋을 `@layer base`로 감싼 뒤 스크린샷에서 여백이 살아났다. 클래스 값과 실제 computed padding이 일치하는 것까지 확인했다.
- 왜 바로 못 찾았나: 빌드와 린트로는 절대 잡히지 않는 종류다. 전부 통과하고 있었다.

## 이어서 나온 같은 원인의 문제
리셋을 고치고 다시 찍어 보니 헤더와 입력창의 위아래 여백만 여전히 0이었다. 레이어 밖에 있던 `.safe-top` / `.safe-bottom`이 같은 요소의 `py-*`를 덮고 있었다. 이것도 `@layer components`로 옮겼다. **원인이 같은 문제는 한 번에 찾아 고치는 게 싸다.**

## 같은 검증에서 나온 다른 버그 (BUG-011)
브라우저로 지시 켜기·끄기를 눌러 보니 403이 떴다.
- 원인: `WebConfig`의 `allowedMethods`에 `PATCH`가 없었다. 개발 서버 프록시(`changeOrigin: true`)를 거치면 Origin과 Host가 달라 Spring이 CORS로 처리하고, 모든 PATCH를 막았다.
- 왜 API 테스트로 못 잡았나: MockMvc와 curl은 Origin 헤더를 붙이지 않는다. **CORS는 브라우저만 재현한다.**
- 고친 뒤 프리플라이트 회귀 테스트를 넣고, 수정 전 코드로 돌리면 실패하는 것까지 확인했다.

## 남은 의문 / 다음에 확인할 것
