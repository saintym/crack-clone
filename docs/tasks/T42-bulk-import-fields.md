## 증상 둘
1. **일괄 등록이 한 덩이 텍스트라 헷갈린다.** 제목(`# 캐릭터 코드`)으로 구역을 가리는 방식이어서, 어느 표가 무엇인지 사용자가 형식을 외워야 한다
2. **새 빌드를 올려도 화면이 안 바뀐다.** 사용자가 "프론트에 접속하니 안 보여"라고 했고, 확인해 보니 서버는 새 빌드를 내보내고 있었다. **서비스 워커가 `index.html`을 프리캐시**해서 캐시된 옛 페이지가 먼저 뜬 것이다

## 구현 내용

### 1. 필드 입구 (`parseFields`)
화면에서 문자열을 조립해 보내지 않고 **칸을 그대로 받는 경로**를 백엔드에 뒀다. 파싱이 한곳에 남는다.
- `parse(spec)`(제목 기반)와 `parseFields(urlTemplate, characters, actions)`가 공통 `assemble`로 모인다
- 각 목록은 한 줄에 `코드: 이름` 하나. 글머리표(`*`, `-`, `+`), 빈 줄, `#` 줄은 무시한다
- **형식이 틀린 줄만 건너뛰고 나머지는 살린다.** 경고에 어느 칸의 어느 줄인지 적는다
- 경고 문구를 칸 이름으로 바꿨다("캐릭터 표가 비어 있습니다. 제목에 `캐릭터`가…" → "캐릭터 목록이 비어 있습니다")

### 2. 세 칸 화면
① 주소 형식(한 줄) ② 캐릭터 목록 ③ 행동·상황 목록.
- 주소 형식 칸은 **입력 중에** `{c}`·`{a}` 유무를 검사해 빨간 글씨로 알린다
- 칸을 고치면 **미리보기 결과를 지운다.** 낡은 결과로 「추가」를 누르지 못하게
- 세 칸이 다 차고 주소가 유효할 때만 미리보기가 켜진다

### 3. PWA 캐시
`index.html` 프리캐시를 끄고 `navigateFallback`을 없앴다. 해시가 붙은 에셋은 그대로 프리캐시한다.

### 2026-09-28
**2번을 찾는 과정이 기록할 만하다.** "안 보인다"는 말에 코드 배선을 먼저 의심했지만 배선은 맞았다. 서버가 실제로 무엇을 내보내는지 확인해서 범위를 좁혔다.

```
서버 index.html이 가리키는 에셋 : /assets/index-CC0wilYz.js
그 에셋에 「주소 규칙으로 일괄 등록」 : 1개 (있음)
```

서버는 새 빌드를 내보내고 있었으므로 **클라이언트 쪽**이다. `dist/sw.js`를 열어 보니 프리캐시 목록에 `index.html`이 있었다. `skipWaiting`·`clientsClaim`이 켜져 있어 새 워커가 바로 제어권을 잡지만, **그 순간 이미 렌더된 페이지는 옛 것**이라 새로고침이 두 번 필요했다.

**해시 에셋과 `index.html`을 다르게 다뤄야 한다.** 해시가 붙은 파일은 내용이 바뀌면 이름이 바뀌므로 캐시가 안전하다. `index.html`은 이름이 고정이라 캐시하면 새 에셋을 가리키는 새 문서를 못 받는다. 그래서 **에셋은 캐시, 화면은 네트워크**로 갈랐다.

**필드 입구를 백엔드에 둔 이유.** 화면에서 `#형식:`·`# 캐릭터 코드` 문자열을 조립해 보내도 됐지만, 그러면 화면이 명세 형식을 알아야 하고 형식이 바뀔 때 양쪽을 고쳐야 한다. **칸을 그대로 받고 파싱은 백엔드에 남겼다.**
