# T43 일괄 등록 시 인물 문서 확인

- **상태**: DONE
- **웨이브**: 8
- **의존**: T41, T42
- **브랜치**: `task/T43-bulk-import-character-check`
- **마이그레이션**: 없음

## 배경
사용자가 물었다. "그럼 이미지 일괄등록하면 무림천하에는 이미지 안 들어가?"

`완안연`·`신소향` 코드표를 무림천하에 등록하면 **파일에는 들어가지만 인물 이미지로는 동작하지 않는다.** 그리고 조용히 더 나쁜 일이 생긴다.

## 무엇이 잘못되는가
태그는 `{인물 문서 파일명}_{변형}`이어야 인물 이미지로 동작한다. `완안연.md`가 없으면:
1. `ActiveCharacterSelector`가 완안연을 고를 수 없다 → **변형 목록이 프롬프트에 안 들어간다** → AI가 `{{img:완안연_기본}}`을 쓸 일이 없다
2. 더 나쁜 것: `ImagesContributor`는 **인물 이름으로 시작하지 않는 태그를 장면·배경 태그로 분류한다.**
   ```kotlin
   val sceneEntries = entries.filter { e -> characterNames.none { e.tag.startsWith("${it}_") } }
   ```
   `완안연_기본`이 **장면 태그 목록에 올라가** AI가 배경 이미지로 끼워 넣을 수 있다

2번이 조용히 지나가면 찾기 어렵다. 인물 이미지가 배경처럼 본문 중간에 뜬다.

## 구현 내용
미리보기·적용 응답의 `warnings`에 한 줄을 더한다.

> 이 시나리오에 인물 문서가 없는 이름입니다: 완안연, 신소향. 이대로 등록하면 인물 이미지로 동작하지 않고 장면·배경 태그로 취급됩니다. 이름을 `characters/{이름}.md`의 파일명과 같게 맞추거나, 그 작품의 시나리오에 등록하세요.

- 이름은 10명까지 나열하고 나머지는 개수로 알린다
- **막지 않고 경고만 한다.** 장면 태그를 일부러 이렇게 넣는 쓰임도 있다
- 인물 목록을 읽지 못하면 경고를 건너뛴다. 등록 자체를 막을 이유는 없다

## 작업 로그

### 2026-09-28
**질문에 답하다가 2번을 발견했다.** 1번(변형 목록이 안 들어간다)은 예상했지만, 인물 이름으로 시작하지 않는 태그가 **장면 태그로 분류된다**는 것은 `ImagesContributor`를 다시 읽다가 알았다. 이름이 안 맞으면 이미지가 "안 나오는" 게 아니라 **엉뚱한 자리에 나온다.**

**막지 않고 경고만 하는 쪽을 택했다.** 인물 이름으로 시작하지 않는 태그는 원래 장면 태그의 정상 형태다(`객잔_밤`). 규칙으로 금지할 수 없고, 사용자가 의도한 것인지 실수인지는 사용자만 안다.

**확인:** 실제 서버로 두 경우를 확인했다.
```
무림천하 + 완안연·신소향 → ⚠ 인물 문서가 없는 이름입니다: 완안연, 신소향
무림천하 + 장수·당월     → 경고 없음, 장수_웃음/당월_웃음 생성
                          (장수_기본·당월_기본은 이미 있어 중복으로 건너뜀)
```
