#### 기록 품질 평가

**수정 전(원래 프롬프트)** — `T22검증` 스토리, 기록 1회(턴 1–3) + 2회(턴 4–6) 결과에서 §7.4 기준 위반을 넷 찾았다.

1. **대사 원문 인용** — 인물 `### 관계`에 `… "돌려받을 거면 살아서 와요"라는 말로 걱정을 내비침 (t6)`. §7.4 "대사 원문은 기록하지 않는다" 위반.
2. **항목이 사건 로그가 됨** — 관계 한 줄이 3문장 130자가 되고, `### 사건`이 같은 내용을 되풀이했다(중복 금지 위반). 정보를 알려 준 일까지 사건으로 쌓여(`t4–5: … 추격자 수를 다시 알려줌`) 매 기록마다 줄이 늘었다.
3. **이미 없는 소지품 잔류** — `냉기를 품은 흰 얼음 조각을 … 건네 … 더는 지니지 않음 (t3–5)`. 넘긴 물건을 지우지 않고 설명만 남겼다. 나을 상처(`등에 부러진 화살 …`)도 "영구적인 신체 변화"에 들어갔다.
4. **`state` 필드 오용** — `"location": "능선(한경)·움막(설하, 분리됨)"`. 인물 상태 패널에 그대로 노출되는 값이다. `"time"`은 `"밤"`으로 예시(`3일차 밤`)와 달리 며칠째가 빠졌다.
5. 연대기가 과하게 상세 — 3턴 범위에 글머리표 7개. 프롬프트가 "3~8개"만 요구해 턴 수와 무관하게 늘어난다.

**수정한 내용** (`memory/record/RecordPrompts.kt`, 태그 이름은 그대로라 파서·Fake 응답은 손대지 않았다)

- 공통 규칙에 두 줄 추가: "한 줄에 한 문장만 쓴다", "대사를 옮겨 적지 않는다(큰따옴표 인용 금지)".
- 시나리오 관리자: 연대기 "**글머리표 수는 범위의 턴 수를 넘기지 않는다**(많아도 8개)", 주고받은 정보의 세부 수치 제외. `location`은 "**주인공이 있는 장소 하나**만", `time`은 "며칠째인지와 시각을 함께".

**아직 남은 문제(다음 사람에게)**

- 앞선 기록이 남긴 **긴 옛 항목은 다시 쓰지 않는다**. `t1–3` 사건 줄과 화살 상처 줄이 그대로 남았다. "기존 항목도 이번 기준에 맞게 다듬어라"를 넣으면 기록마다 문서 전체가 흔들려 되돌리기 diff가 커진다 — 압축 단계(§7.2 ④)에 맡기는 편이 맞아 보인다.
- **다 쓴 물건**(얼음 조각)을 주인공 `### 소지품`에서 지우지 않고 "…쓰는 데 씀"으로 남겼다. "넘긴/잃은" 외에 "소모한"도 명시해야 한다.
- `time`에 며칠째가 계속 안 붙는다. 원문에 날짜 표기가 없으면 모델이 만들지 않는다. 시나리오 문서에 시간 기준을 적어 두는 쪽이 현실적이다.
- 비용 지침에 따라 **수정 후 1회 재실행까지만** 비교했다. 더 다듬으려면 같은 절차(되돌리기 → `/기록`)를 쓰면 된다.
