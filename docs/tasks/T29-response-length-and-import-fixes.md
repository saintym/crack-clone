## 목표
실제 플레이에서 확인된 세 가지를 고친다.
1. 응답 분량에 상한이 없어 계속 길어졌다(720자 → 2,032자, 지연 17.5초 → 35.5초). **목표 분량 800~1,500자**를 프롬프트에 넣고, 전역 기본값 + 시나리오별 조정을 지원한다
2. 프롤로그에 화자 태그가 없어 첫 메시지에는 이미지가 붙지 않는다
3. 가져오기가 미분류 이미지를 중복 태그로 등록한다([BUG-024](../../bugs/BUG-024_미분류_이미지가_중복_태그로_등록됨.md))

## 구현 내용

### 1. 응답 분량 지시 (D33)
- 설정: `crack.prompt.response-chars.min`(기본 800), `max`(기본 1500)
- `BaseContributor`가 출력 형식에 한 줄 넣는다: 예) `분량은 한 응답에 약 800~1,500자를 목표로 한다. 장면이 짧게 끝나야 할 때는 더 짧아도 되지만, 2,000자를 넘기지 마라.`
- **기존 "최소 200자" 문구는 지운다.** 지금 문구가 하한만 있어 길어지는 원인이다

### 2. 시나리오별 조정
- 스토리 폴더에 `settings.json`(선택)을 둔다. 형식: `{"responseChars": {"min": 1200, "max": 2200}}`
- 시나리오 원본에 있으면 스토리 생성 시 복사한다(T08 복사 목록에 추가). 없으면 전역 기본값을 쓴다
- 스토리 문서 API의 화이트리스트에 `settings.json`을 넣어 기억 패널에서 고칠 수 있게 한다
- 값이 깨졌거나 범위가 이상하면(min > max, 음수) 경고 로그를 남기고 전역 기본값을 쓴다

### 3. 프롤로그 화자 태그
- 가져오기(`ImportPrompts`)가 `prologue.md` 첫 줄에 `[인물: 이름/변형]`을 쓰게 한다. 첫 장면에 인물이 없으면 생략한다
- `data/_templates/prologue.md` 안내에도 형식을 적는다(사람이 직접 쓸 때도 쓸 수 있게)
- 서버 파싱은 이미 T27에서 된다. 새로 만들 필요 없다

### 4. 미분류 이미지 주석 (BUG-024)
- 인물과 매칭되지 않은 이미지는 `<!-- 미분류 이미지 N: URL — 쓰려면 주석을 풀고 태그 이름을 정하세요 -->`로 남긴다
- 이미 만들어진 두 시나리오 파일은 오케스트레이터가 수동 정리했다. 코드만 고치면 된다
- `bugs/README.md`와 BUG-024 상태를 갱신한다
