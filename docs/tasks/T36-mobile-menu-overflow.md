# T36 좁은 화면에서 메시지 메뉴가 화면 밖으로 나가는 문제

- **상태**: DONE
- **웨이브**: 8
- **의존**: T31, T32
- **브랜치**: `task/T36-mobile-menu-overflow`
- **마이그레이션**: 없음

## 증상
핸드폰에서 **내가 쓴 메시지**의 `⋯` → 수정·분기·삭제 메뉴가 화면 밖에 그려져 보이지 않는다.

## 원인
T31에서 소설 모드를 기본값으로 바꾸면서 **액션 줄의 정렬이 바뀐 것과, 메뉴가 방향을 정하는 기준이 어긋났다.**

```
MessageList  소설 모드에서는 유저 메시지 줄에 justify-end를 주지 않는다 → 줄이 화면 왼쪽 끝
MessageMenu  그런데 isUser면 여전히 flex-row-reverse → ⋯ 버튼이 그룹의 왼쪽
MessageMenu  isUser면 드롭다운이 right-0 → 버튼 오른쪽 끝에서 왼쪽으로 펼쳐짐 → 화면 밖
MessageMenu  삭제 확인 패널은 w-56(224px)이라 더 심하다
```

**`isUser`로 정렬을 정한 것이 근본 원인이다.** 유저 메시지가 오른쪽에 붙는다는 전제가 소설 모드에서 깨졌다.

## 범위
- `crack-frontend/src/components/chat/MessageMenu.tsx`
- `crack-frontend/src/components/chat/MessageList.tsx`

## 구현 내용
1. `MessageMenu`의 `isUser: boolean` prop을 **`align: 'left' | 'right'`**로 바꿨다. 누가 쓴 메시지인지가 아니라 **줄이 화면의 어느 쪽에 붙어 있는지**를 받는다
2. `MessageList`가 `align={isUser && !novel ? 'right' : 'left'}`로 넘긴다. 소설 모드는 전부 `left`
3. 드롭다운에 **`max-w-[calc(100vw-1.5rem)]`** 상한을 뒀다. 앞으로 어떤 정렬 조합이 와도 화면 밖으로 나가지 않는다
4. 삭제 확인 패널 `w-56` → `w-56 max-w-full`로 상한을 상속받게 했다

## 다른 팝오버 점검
| 위치 | 상태 |
|---|---|
| `ChatHeader` 프로바이더 메뉴 | 문제 없다. 버튼이 화면 오른쪽 끝에 있고 `right-0 min-w-[180px]`로 왼쪽으로 펼쳐진다. 320px 화면에서도 왼쪽 끝이 x=124 |

## 작업 로그

### 2026-09-28
사용자가 핸드폰에서 발견했다. "내가 쓴 말의 수정 버튼을 누르면 메뉴가 화면 밖에 표시돼서 안 보여. 다른 버튼들도 그런지 확인해봐."

**T31이 만든 회귀다.** 소설 모드에서 좌우 정렬을 없애면서 유저 메시지 줄이 왼쪽으로 옮겨졌는데, 메뉴는 여전히 "유저 메시지는 오른쪽에 있다"는 전제로 방향을 정하고 있었다. T31에서 `MessageList`의 `justify-end`는 고쳤지만 **`MessageMenu`에 넘기는 `isUser`는 그대로 뒀다.**

**prop 이름을 `isUser`에서 `align`으로 바꾼 것이 고침의 핵이다.** 컴포넌트가 "누가 쓴 메시지인지"를 알 필요가 없다 — 알아야 하는 것은 "어느 쪽으로 펼칠지"뿐이다. 잘못된 추상이 회귀를 불렀다.

**폭 상한을 같이 넣었다.** 정렬을 고치면 이번 건은 해결되지만, 다음에 또 레이아웃을 바꾸면 같은 종류의 버그가 난다. `max-w-[calc(100vw-1.5rem)]`은 방향이 어떻든 화면을 넘지 않게 한다.

**다른 팝오버는 전부 문제가 없었다**(위 표). 공통점이 있다 — 화면 끝에 고정된 것(헤더 메뉴)이나 부모 폭을 그대로 쓰는 것(`inset-x-0`), 하단 시트는 안전하다. **위험한 것은 "내용만큼의 폭"을 가진 요소가 화면 끝 근처에 있을 때**다.

**확인:** 프론트 build·lint 통과. `dist`를 다시 빌드해 터널에도 반영했다(백엔드는 `dist`를 파일 경로로 읽으므로 jar 재빌드가 필요 없다).

**다음 작업자에게:**
- 레이아웃 정렬을 바꿀 때는 `MessageMenu`의 `align`을 같이 본다. 이 prop이 `MessageList`의 정렬과 짝이다
- 소설 모드에서 메뉴는 `opacity-35`다(T31). 터치 기기에는 hover가 없어 계속 흐리게 보인다 — 아직 남아 있는 과제다
