## 작업 로그

### 2026-09-27
「봄의귀환이후」로 20턴 자동 플레이를 돌려 인물 말투를 검증하던 중, 턴 16에서 모델이 이렇게 뱉었다.

```
This is a roleplay continuation. Let me write Sakura's response in character.

---

[감정: 수줍음, 걱정] [인물: 사쿠라]
```

`EmotionTagFilter`는 응답 **맨 앞**만 버퍼링해 태그를 소비한다. `This is…`는 `[`로 시작하지 않으므로 첫 delta에서 바로 통과 상태가 되고, 뒤에 온 태그 줄은 그냥 본문이 됐다. 20턴 중 1회.

**필터의 버그가 아니라 필터의 전제를 AI가 깬 것**이라, 프롬프트를 먼저 고치고 안전망을 뒤에 뒀다.

**안전망의 조건을 일부러 좁게 잡았다.** 줄 전체가 태그여야 하고, 버릴 양이 300자를 넘으면 포기한다. 본문 중간의 대괄호(`[무언가]`)는 건드리지 않는다. **본문을 지우는 쪽이 태그가 잠깐 보이는 쪽보다 나쁘다**는 판단이다.

**스트리밍 중에는 회수하지 않는다.** 이미 흘려보낸 delta를 되돌릴 수 없고, 화면에서 글자를 뒤늦게 지우면 글이 튄다. 저장되는 본문과 `speaker`는 회수를 거친 값이므로 턴이 끝나면 깨끗해진다. 프론트에도 같은 회수를 넣었지만 **스트리밍이 끝난 뒤에만** 적용해서, T33 이전에 저장된 메시지도 화면에서는 정상으로 보인다.

**확인:** 백엔드 550개 통과(신규 6개), 프론트 build·lint 통과.

**다음 작업자에게:**
- `MAX_PREAMBLE_LINES`·`MAX_PREAMBLE_CHARS`는 백엔드와 프론트 양쪽에 같은 값으로 박혀 있다. 한쪽만 고치면 어긋난다
- 스트리밍 중 메타 문장이 잠깐 보이는 것은 남아 있다. 이걸 없애려면 필터가 응답 앞부분을 더 오래 버퍼링해야 하는데, 그러면 첫 글자가 늦게 뜬다. 지금은 프롬프트로 막는 쪽을 택했다
