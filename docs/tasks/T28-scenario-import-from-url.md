# T28 URL에서 시나리오 가져오기

- **상태**: IN_PROGRESS
- **웨이브**: 8
- **의존**: T27 (이미지 카탈로그 자동 등록에 `{이름}_기본` 규칙을 쓴다)
- **브랜치**: `task/T28-scenario-import-from-url`
- **마이그레이션**: 없음 (필요하면 V9. DESIGN.md를 먼저 고친다)
- **결정**: D32

## 목표
설정이 정리된 웹페이지 URL을 주면, AI가 읽어서 **시나리오 한 벌**(세계관·시나리오·인물 전원·주인공·첫 메시지·키워드북·이미지 카탈로그)을 만들어 등록한다. 지금은 문서를 손으로 다 써야 시나리오를 만들 수 있다.

## 예시 입력 (실측)
| | `https://jangsue.uk/MG/web.html` | `https://jangsue.uk/HT/FWeb.html` |
|---|---|---|
| HTML | 62,207자 | 395,817자 |
| 인물 데이터 | `const chars = [{name, alias, faction, org, rank, age, gender, mbti, keywords, img, sk, vignette}, …]` 약 25명 | `const CHARACTERS`, `ORGS`, `RANKS`, `WORLDS`, `EPISODES` |
| 본문 텍스트 | 28,034자 | 32,685자 |
| 이미지 URL | 28개 (인물 데이터의 `img` 필드) | 28개 |
| 외부 JS/JSON | 없음 (한 파일에 모두 있음) | 없음 |

페이지마다 형식이 다르다. **규칙 파싱이 아니라 LLM이 읽어서 우리 형식으로 옮기는 방식**으로 간다. 단 추출 단계에서 토큰을 줄인다.

## 범위
- 신규 `crack-backend/src/main/kotlin/com/crack/scenario/import/**` (가져오기 파이프라인)
- `scenario/controller/ScenarioController.kt`(엔드포인트 추가) 또는 신규 컨트롤러
- 프론트: 신규 `src/components/scenario/ScenarioImport*.tsx`, `src/api/scenarios.ts`, `src/pages/ScenariosPage.tsx`(버튼)
- `docs/DESIGN.md`(새 절: 가져오기 API와 파이프라인), 관련 테스트

## 구현 내용

### 1. 추출 (LLM 호출 전)
1. HTML을 가져온다. **상한: 5MB, 타임아웃 20초.** `text/html`만 허용
2. **SSRF 방어(필수).** `http`/`https`만, 사설·루프백·링크로컬 대역 차단(127.0.0.0/8, 10/8, 172.16/12, 192.168/16, 169.254/16, `::1`, `localhost` 등). DNS 해석 결과 IP로 검사한다. 리다이렉트도 매 홉 검사
3. 추출물 세 덩어리
   - **본문 텍스트**: `<script>`·`<style>` 제거 후 태그 제거, 공백 정리
   - **데이터 블록**: `<script>` 안의 `const X = [...]` / `{...}` 리터럴을 **원문 텍스트로** 잘라 온다(인물 배열이 여기 있다)
   - **이미지 URL 목록**: `src`/`href`와 데이터 블록에서 수집. 절대 URL로 정규화
4. 상한을 넘으면(기본 합계 150,000자) 본문은 앞에서 자르고 데이터 블록을 우선 남긴다. 무엇을 잘랐는지 응답에 적는다

### 2. 1단계 API — 분석
`POST /api/scenarios/import/analyze` body `{url}` → `{jobId, suggestedName, title, characters:[{name, alias, org, imageUrl}], imageCount, questions:[{id, text, placeholder}], truncated}`
- LLM 1회(purpose CHAT): 페이지에서 시나리오 제목 후보, 인물 목록, **사용자에게 물을 질문 3~5개**를 뽑는다
- 질문은 페이지에 없는 것만 만든다. 이 두 페이지는 설정집이라 주인공이 없다 → 주인공 이름·성별·소속 세력·시작 시점·목표 같은 것을 묻는다
- `jobId`로 추출 결과를 서버 메모리에 캐시(TTL 30분). DB 테이블은 만들지 않는다

### 3. 2단계 API — 생성
`POST /api/scenarios/import/{jobId}/confirm` body `{name, answers:{questionId: 답}}` → **SSE**로 진행 상황
- 이벤트: `step`(단계 이름과 진행률), `done`(scenarioId, 만든 파일 목록), `error`
- 단계
  1. `world.md`, `scenario.md`, `keywords.md` (LLM 1회)
  2. `characters/{이름}.md` — **페이지의 인물 전원**. 3~5명씩 배치, 동시 실행 3 (`crack.import.concurrency`)
  3. `characters/protagonist.md`, `prologue.md` — 사용자 답변 반영 (LLM 1회)
  4. `images.md` — 인물 데이터의 이미지 URL을 `{이름}_기본`으로 등록(T27 규칙). 인물과 매칭 안 되는 이미지는 장면 태그 후보로 주석 처리해 둔다
- **원자적 생성**: 임시 폴더에 다 만든 뒤 시나리오 폴더로 옮기고 DB에 등록한다. 중간 실패면 임시 폴더를 지우고 아무것도 남기지 않는다
- 같은 이름의 시나리오가 이미 있으면 400(덮어쓰기 금지)

### 4. 문서 형식 (중요)
생성 결과는 **우리 파서와 호환돼야 한다.** 맞지 않으면 기억 기록과 상태 패널이 깨진다.
- 인물 문서: `data/_templates/character.md` 구조를 따른다. `- **이름**:`, `- **별칭**: a, b`(있으면), 외모·성격·말투·배경. **`## 기억` 섹션은 빈 상태로 둔다**(T05 `CharacterDoc`가 파싱한다)
- 주인공 문서: `_templates/protagonist.md` 구조 + `## 변화 기록` 빈 섹션
- `keywords.md`: `## 제목` + `키워드: a, b` + 내용 (T06 파서 형식). 세력·지명·용어를 항목으로
- 파일명은 인물 이름 그대로. 경로 조각 하나여야 한다(`/`, `..`, 공백만 있는 이름 거부). 중복 이름은 뒤에 숫자를 붙인다
- 생성된 문서 맨 아래에 출처 한 줄을 남긴다: `<!-- 출처: {url} (자동 생성 {날짜}) -->`

### 5. 프론트
- 시나리오 목록에 **"URL로 가져오기"** 버튼 → 단계형 화면
  1. URL 입력 → 분석 중 표시
  2. 분석 결과(제목 후보, 인물 수와 목록, 이미지 수)와 **질문 3~5개 입력 폼**. 시나리오 이름 수정 가능
  3. 생성 진행 표시(단계별, SSE). 인물 25명이면 수 분 걸린다는 안내
  4. 완료 → 시나리오 상세로 이동. "문서를 확인하고 다듬으세요" 안내
- 실패 시 어느 단계에서 왜 실패했는지 보여 준다

### 6. 비용·시간 안내
- LLM 호출은 대략 `1(분석) + 1(세계관) + ceil(인물수/4) + 1(주인공)` 회다. 25명이면 약 10회, 한 번에 15~40초이므로 3~6분이 걸린다. 화면에 예상 시간을 표시한다
