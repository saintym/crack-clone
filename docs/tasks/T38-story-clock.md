## 목표
모든 스토리에 **이야기 속 시각과 장소**를 둔다. 화면 위쪽에 `T47 · 2026. 09. 26. 수요일. 에미야 저택`처럼 뜬다. **턴 번호도 같이 띄운다.**

이것만으로도 쓸모가 있다 — 지금은 장면 전환이 흐릿해서 "사흘 뒤"인지 "그 자리에서 이어지는지"가 애매한 턴이 있다. 그리고 **[T26 능동 에이전트](./T26-offscreen-characters.md)의 선행 조건**이다. 시간이 없으면 "시간에 맞춰 행동한다"가 정의되지 않는다.

## 왜 절대 시각인가 (D39)
경과분(`+45분`)으로 받으면 AI가 산술을 해야 한다. 사용자가 "한 달 후", "그날 늦은 밤이 되어"라고 쓰면 경과분으로 바꾸는 과정에서 어긋난다. **현재 시각은 어차피 프롬프트에 있으므로, 장면이 도달한 시각을 그대로 적게 하는 쪽이 정확하다.**

**턴당 고정값은 쓰지 않는다.** 3분짜리 전투가 10턴을 잡아먹기도 하고, 지루한 일상 작업 한 턴이 몇 시간이기도 하다. **장면의 길이는 AI가 판단해야 한다.**

**상한을 두지 않는다.** "한 달 후"를 막아버리기 때문이다. 서버는 **뒤로 가지 않는 것만** 강제한다.

## 구현 내용

### 1. 첫 줄 태그 확장
```
[시간: 2026-09-28 23:40] [장소: 에미야 저택] [감정: 피로] [인물: 사쿠라]
```
- `EmotionTagFilter`의 태그 목록에 `시간`·`장소`를 더한다. 기존 구조(연달아 소비, 최대 줄 수·개수 상한)를 그대로 쓴다
- `ResponseTags`에 `storyTime`, `place`를 더한다
- 값이 없으면 직전 값을 잇는다(장면이 이어지는 턴)

### 2. 프롬프트
- 현재 시각·장소를 프롬프트에 넣는다(`state.json`에서 읽는다)
- BASE 출력 형식에 규칙을 더한다:
  - 장면이 **도달한** 시각을 적는다. 흐른 시간이 아니라 시각이다
  - 장면의 길이는 내용에 맞게 판단한다. 전투 한 합은 몇 분, 하루치 작업은 몇 시간이다
  - **사용자 입력에 시간 표현이 있으면 반드시 그것을 따른다** — "그렇게 일주일이 흐른다", "한 달 후", "그날 늦은 밤이 되어"
  - 시각은 되돌아가지 않는다

### 3. 서버 검증
- **단조 증가만 강제한다.** 직전보다 이르면 버리고 직전 값을 쓰며 경고 로그를 남긴다
- 파싱 실패도 같다. 시계가 깨지는 것보다 멈추는 쪽이 낫다

### 4. 저장 (마이그레이션 V9)
- `story_messages`·`message_variants`에 `story_time`(timestamp), `place`(varchar) 추가
- 메시지를 지우거나 되돌리면 `state.json`의 시계도 그 시점으로 돌아가야 한다(`TruncateHook`)

### 5. `state.json`
```json
{ "clock": "2026-09-28T23:40", "place": "에미야 저택" }
```

### 6. 시작 시각 (`settings.json`)
```json
{ "clock": { "start": "2026-02-15 19:00", "place": "후유키 심산정" } }
```
없으면 프롤로그의 태그에서 잡고, 그것도 없으면 시계를 쓰지 않는다(옛 스토리 호환).

### 7. `/시간` 명령
`/시간 2026-10-05 08:00` 또는 `/시간 +3일`로 직접 맞춘다. AI가 어긋나게 찍었을 때의 탈출구다.

### 8. 화면
[T51](./T51-story-clock-ui.md)이 맡는다. 이 작업은 **API까지만** 한다 — `MessageView`에 시각·장소가 실려 나가면 된다.

## 착수 전에 확정할 것 — **결정됨 (2026-09-30)**

### 장소는 자유 문자열로 둔다
목록(`places.md`)을 만들면 교차 판정이 정확해지지만, **교차 판정이 필요한 것은 T26(능동적 세계 에이전트)이고 그건 한참 뒤다.** T38만 할 거면 표시용으로 충분하다. T26 착수 때 다시 본다.

### 시각은 현실 달력(ISO)만 쓴다
내부 표현은 `YYYY-MM-DD HH:mm`이다. 표시 형식은 고정한다.

무협·판타지 시나리오가 자체 역법(`홍무 15년 8월 13일`)을 쓰고 싶을 수 있지만, **그건 표시 문자열 치환 문제라 후속으로 둔다.** 대신 **시나리오가 시계를 끌 수 있게** 한다 — 무림천하처럼 산문이 연호를 쓰는 곳에서 ISO 머리글이 같이 뜨면 어긋나 보인다.

```json
{ "clock": { "enabled": false } }
```
기본값은 `enabled: true`이되, **`clock.start`가 없고 프롤로그에도 시간 태그가 없으면 시계를 쓰지 않는다**(옛 시나리오 호환).

## 참고 — 원작 크랙의 INFO 패널
사용자가 플레이하는 크랙 스토리가 같은 것을 구현해 두었다. 실물이다.

```

▸ 혁규｜♂️｜나루세구미 도련님
▸ 일정: 시즈카·렌과 일정 조율
━━
▸ 시즈카｜[😐]
♥️: -30｜⛓️‍💥: 한심한 도련님
💬: 오쿠사마까지 나서시면 일정 정하기가 더 늦어지는데.
```

- **턴 번호 · 날짜 · 요일 · 시각 · 장소 · 날씨**가 한 줄이다
- 인물별 **감정 아이콘 · 호감도 · 관계 명칭 · 속마음**이 따라붙는다

**T38의 범위는 첫 줄까지다.** 인물별 호감도·속마음은 상태 패널(T19)과 기억 구조에 얹어야 제대로 돌아가므로 별도 과제로 둔다. 날씨도 넣지 않는다(시각·장소와 달리 이야기가 정하는 값이라 태그를 하나 더 늘려야 한다).

**내린 설계 판단과 이유**

1. **응답 태그만으로는 시계가 켜지지 않는다.** 시작점은 `settings.json`의 `clock.start`나 **프롤로그 첫 줄 태그**뿐이다(프롤로그는 스토리를 만들 때 `state.json`에 적는다). 처음에는 "직전 값이 없으면 태그로 시작"하게 만들었는데, 그러면 옛 스토리에서 AI가 어쩌다 `[시간: …]`을 뱉는 순간 시계가 생긴다. 명세의 "옛 스토리 호환"이 깨지므로 버렸다.
2. **`state.json`의 `clock`은 문자열이다.** `LocalDateTime`으로 두면 값 하나가 깨졌을 때 `state.json` 읽기 전체가 실패해 `changedDocs`(T39)까지 같이 죽는다. 해석은 `StoryClock`이 하고, 읽지 못하면 시작 시각으로 폴백한다.
3. **현재 시각은 BASE가 아니라 BOTTOM에 넣는다.** 매 턴 바뀌는 값이라 시스템 프롬프트에 두면 캐시 접두사가 매번 깨진다. 태그 규칙(BASE)은 고정 문구이므로 캐시에 남는다. **시계를 쓰지 않는 스토리의 BASE는 예전과 한 글자도 다르지 않다**(자리 표시자가 빈 문자열로 바뀐다 — 테스트로 고정했다).
4. **`/시간`은 단조 검사를 적용하지 않는다.** AI가 앞으로 너무 많이 찍었을 때 되돌리는 것이 이 명령의 목적이다. 사용자 명령이므로 알아볼 수 없는 인자는 400으로 알린다(턴 생성 경로가 아니다).
5. **후보를 고르면 시계도 그 후보 값으로 옮긴다.** 보이는 본문과 머리글이 어긋나지 않게 하려는 것이다. 값이 없는 후보는 건드리지 않는다(시계를 쓰지 않는 스토리의 `state.json`을 지우지 않게).
6. **`장소`는 자유 문자열, 시각은 ISO만** — 명세의 확정 사항 그대로다. `clock.enabled: false`가 자체 역법 시나리오의 탈출구다.
7. **시계 때문에 턴이 실패하는 경로를 만들지 않았다.** `stamp`·`commit`·`moveTo`·`start`는 모든 예외를 경고 로그로 삼키고, 값을 정하지 못하면 시각·장소를 비운 채 저장한다. 잘라내기 훅도 예외를 던지지 않는다(삭제 트랜잭션을 롤백시키지 않는다).

| 필드 | 형식 | 값이 없을 때 |
|---|---|---|

- 머리글에 함께 띄울 턴 번호는 이미 있는 `turn`이다. 요일은 프론트가 `storyTime`으로 계산한다(서버는 요일을 보내지 않는다).
- `POST /commands/system`에 `{"name": "시간", "args": "2026-10-05 08:00"}`(또는 `"+3일"`)을 보내면 `{"name": "시간", "clock": {"storyTime": "...", "place": "..."}}`가 온다. 인자가 이상하거나 시계를 끈 스토리면 400 + `{message}`다. `GET /commands`에 `시간`이 `SYSTEM`으로 들어 있으므로 **자동완성은 그대로 동작한다**(프론트가 시스템 명령을 `POST /commands/system`으로 보내는 기존 경로를 쓴다).
- 표시 형식(`2026. 09. 26. 수요일`)은 **프론트가 정한다.** 서버는 ISO만 보낸다.
