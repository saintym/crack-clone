## 목표
인물이 **프롬프트에 자료가 있다는 이유로** 모든 것을 아는 것처럼 말하고 행동하는 문제를 고친다. 주인공의 과거, 다른 인물의 비밀, 시간·공간 제약을 전부 무시하고 있었다.

## 원인
프롬프트가 문서를 그대로 쏟아붓고, **누가 무엇을 아는지에 대한 정보가 프롬프트에 아예 없었다.**

```kotlin
// 이전
StoryDocs.titled("주인공(사용자)", it)                      // protagonist.md 전문
selector.select(ctx).joinToString { StoryDocs.titled("캐릭터: ${it.name}", it.text) }  // 인물 문서 전문
```

모델 입장에서 주어진 컨텍스트 전부가 공유 지식이다. 20턴 검증에서 잡힌 예: 우혁규가 이름을 **소리로만** 말했는데 린이 *"**우(禹)라는 성은** 시계탑의 명부에서 본 적이 없다"*고 서술했다. 한자는 `protagonist.md`에만 있다.

## 버린 방향
**인물별로 프롬프트를 쪼개 각각 호출하기.** 가장 정확하지만 매 턴 LLM을 여러 번 부른다. **제품 원칙("매 턴 응답 전에는 LLM을 추가로 호출하지 않는다")에 정면으로 어긋난다.**

## 구현 내용
DESIGN.md §6.5가 기준이다. 요약하면 네 조각이다.

1. **`(비공개)` 섹션 규약** — `##` 제목이 `(비공개)`로 끝나면 기본적으로 아무 인물도 모르는 정보다. `PrivateSections.render`가 **공개 → `[비공개]` 라벨 → 비공개** 순서로 재배치한다. 내용은 빠지지 않는다
2. **`## 알고 있는 것`(사람) + `## 기억`(AI)** — 아는 사람의 예외 목록. **인물마다 아는 사람과 모르는 사람이 갈리는 것이 이 구조로 표현된다**
3. **BASE 인지 규칙** — 안다고 쓸 수 있는 경우를 셋으로 못 박는다
4. **기록 프롬프트 예외** — "숨겨져 있던 중요한 사실을 알게 되었으면 반드시 사건으로 적는다"

## 작업 로그

### 2026-09-28
사용자가 플레이 중 지적했다. "캐릭터들이 몰라야 하는 사실을 이미 다 알고 들은 듯이 행동해. 주인공의 정보나 타 캐릭 문서에 적힌 내용을 시간과 공간의 제약, 실제로 알고 있는지 여부를 무시하고 전부 아는 것처럼 말하고 행동한다."

그리고 정확한 후속 질문을 받았다. **"도중에 말해서 알게 되면? 인물마다 아는 인물과 모르는 인물이 생겨날 텐데 그때는?"** 섹션 단위 `(비공개)`는 이진 플래그라 그것만으로는 답이 안 된다.

**해결의 핵은 "비공개 플래그를 모른다의 기본값으로만 쓰는 것"이다.** 누가 아는지는 비공개 섹션에 적지 않고 **그 인물 문서 쪽에** 적는다. 린이 알게 되면 `린.md`에 그 줄이 생기고 `사쿠라.md`에는 없다 → 사쿠라는 모른다. 인물마다 갈리는 것이 저절로 표현된다.

**"도중에 알게 되면"은 대부분 자동으로 해결된다.** 인지 규칙의 세 번째 조건이 "대화 원문에서 듣거나 보는 자리에 있었다"이므로, 원문이 프롬프트에 있는 동안은 원문이 증거다. 문서를 고칠 필요가 없다. 원문 창을 벗어난 뒤는 기억 기록이 `## 기억`에 남긴다 — **이미 있는 파이프라인이다.**

**기록 프롬프트에서 충돌을 발견했다.** `### 사건` 규칙에 *"이야기를 나눈 일, **정보를 알려 준 일**, 함께 이동한 일은 사건이 아니다"*가 박혀 있었다. T22에서 인물 문서를 30% 줄이려고 넣은 규칙인데, 지식 추적과 정면으로 부딪힌다. 규칙을 지우지 않고 **예외만 좁게 뒀다** — "숨겨져 있던 중요한 사실을 알게 되었으면 반드시 적는다". 일상적인 정보 교환은 여전히 안 적는다.

**`## 알고 있는 것`을 `## 기억`과 따로 둔 이유.** `## 기억`은 기계가 쓰고 예산을 넘으면 압축된다. 사람이 정한 초기 설정을 거기 두면 압축에서 지워질 수 있다. 압축은 `withMemorySection`으로 `## 기억`만 건드리므로, 별도 섹션은 안전하다.

**공개/비공개 경계에서 걸린 것들.** 주인공 문서의 `## 기본 정보` 별칭에 "개대가리, 광견"이 들어 있었다 — 공개 섹션인데 비밀이다. 별칭을 "혁규"만 남기고 나머지를 `## 처지 (비공개)`로 옮겼다. `## 외모`의 마술각인도 "우가에 대대로 이어진 것"이라 적혀 있었는데, 각인 자체는 보이지만 **어느 가문 것인지는 보아도 모른다**로 갈랐다.

**확인:** 백엔드 562개 통과(신규 6개). 프롬프트 구조 실측 — `protagonist` 섹션에서 외모(94) → 성격(255) → 현재 상태(623) → `[비공개]`(768) → 배경(816) → 처지(1666) 순서. BASE는 1,715자 → 2,478자.
