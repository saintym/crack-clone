## 목표
실제 브라우저에서 실제 CLI 응답으로 UI 전체를 조작해 본다. 지금까지 프론트 확인은 작업별 부분 검증이었다. **사용감과 조작 흐름**에서 문제를 찾는 것이 목적이다.

## 실행 환경 (오케스트레이터가 준비해 둠)
- PostgreSQL Docker `crack-postgres`(localhost:5432, `crack`, postgres/artl0108), Flyway V1~V7 적용
- 백엔드 :8082 실행 중(`--crack.data-path=/Users/mayfly/work/crack-clone/data --crack.memory.record.every-turns=3`), 프로바이더 `claude-code-cli`
- 프론트는 직접 띄운다: `cd crack-frontend && npm run dev` (기본 :5173, 프록시 → :8082)
- 로그인 비밀번호는 `crack-backend/src/main/resources/application.yml`의 `crack.auth.password` 기본값
- 시나리오: `마도생존기`(id 1, 실데이터), `테스트세계`(id 2). **T22가 병렬로 백엔드를 검증 중이니, 너는 새 스토리를 만들어 쓰고 T22의 스토리는 건드리지 마라**

## 확인할 항목
1. **로그인 → 시나리오 목록 → 스토리 목록 → 채팅** 흐름
2. **채팅**: 전송 중 표시, 토큰 단위 스트리밍이 실제로 부드럽게 보이는지, 프롤로그, 빈 Enter 이어쓰기, 재생성과 `‹ n/m ›` 후보 넘기기, "지시하고 재생성", 유저·AI 인라인 수정, "수정됨" 표시, 삭제 확인, 분기
3. **감정 태그가 화면에 절대 보이지 않는지**
4. **오른쪽 패널 3탭**: 기억(문서 보기·편집, 기록 이력, diff, 되돌리기, 지금 기록), 지시(추가·토글·수정·삭제), 상태(위치·동행·주인공·인물 카드). 기억 뱃지가 기록 후 뜨는지
5. **`/` 명령**: 자동완성, `/ooc 내용`, `/ooc` 단독(패널 열림), `/기록`, 사용자 정의 명령, 없는 명령
6. **시나리오 편집**: 첫 메시지·세계관·인물·키워드북·명령·이미지 탭 편집과 저장
7. **이미지**: `images.md`에 실제 접근 가능한 외부 URL(예: 위키미디어 등 공개 이미지) 몇 개를 등록하고, AI 응답에 `{{img:태그}}`가 나올 때 실제로 그려지는지
8. **반응형**: 데스크톱(1280)과 모바일(390) 둘 다. 여백·스크롤·하단 시트·입력창
9. **접근성·사용성 관찰**: 버튼 위치, 대기 중 피드백, 오류 메시지 문구 등 개선할 점

## 규칙
- 시나리오 원본 문서는 UI의 편집 기능을 검증할 때만 고치고, 고친 내용은 원래대로 되돌려라(백업: `/Users/mayfly/work/crack-clone-data-backup-202609240013`)
- Playwright는 로컬 npx 캐시를 쓴다(브라우저 버전이 안 맞으면 캐시에 있는 headless shell을 `executablePath`로 지정). 스크린샷은 스크래치에 저장하고 저장소에 커밋하지 마라
- CLI 호출은 사용자 구독을 쓴다. 필요한 만큼만 돌려라
- 발견한 버그는 `bugs/BUG-0NN_*.md`로 등록하고 `bugs/README.md`에 추가한다. **T22와 번호가 겹치지 않게 `BUG-020`부터 쓴다.** 프론트 한 파일 수준의 작은 수정은 직접 고치고(빌드·린트 통과), 큰 것은 등록만 하고 보고하라
