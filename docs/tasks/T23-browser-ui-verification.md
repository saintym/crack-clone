## 확인할 항목
1. **로그인 → 시나리오 목록 → 스토리 목록 → 채팅** 흐름
2. **채팅**: 전송 중 표시, 토큰 단위 스트리밍이 실제로 부드럽게 보이는지, 프롤로그, 빈 Enter 이어쓰기, 재생성과 `‹ n/m ›` 후보 넘기기, "지시하고 재생성", 유저·AI 인라인 수정, "수정됨" 표시, 삭제 확인, 분기
3. **감정 태그가 화면에 절대 보이지 않는지**
4. **오른쪽 패널 3탭**: 기억(문서 보기·편집, 기록 이력, diff, 되돌리기, 지금 기록), 지시(추가·토글·수정·삭제), 상태(위치·동행·주인공·인물 카드). 기억 뱃지가 기록 후 뜨는지
5. **`/` 명령**: 자동완성, `/ooc 내용`, `/ooc` 단독(패널 열림), `/기록`, 사용자 정의 명령, 없는 명령
6. **시나리오 편집**: 첫 메시지·세계관·인물·키워드북·명령·이미지 탭 편집과 저장
7. **이미지**: `images.md`에 실제 접근 가능한 외부 URL(예: 위키미디어 등 공개 이미지) 몇 개를 등록하고, AI 응답에 `{{img:태그}}`가 나올 때 실제로 그려지는지
8. **반응형**: 데스크톱(1280)과 모바일(390) 둘 다. 여백·스크롤·하단 시트·입력창
9. **접근성·사용성 관찰**: 버튼 위치, 대기 중 피드백, 오류 메시지 문구 등 개선할 점

| 구간 | 값 |

#### 사용성 개선 제안 (우선순위)

**P1 — 고쳐야 한다**
1. **(BUG-021) 인증이 사실상 없다.** 10자 넘는 아무 문자열이면 통과한다. 공개 저장소 + `allowedHosts: true`라 밖에 열면 위험하다. 토큰에 만료를 붙여 HMAC 서명하자.
2. **첫 6~7초 침묵.** 점 3개만으로는 "멈춘 건가?" 싶다. 3초가 지나면 경과 초(`12초째 생성 중…`)나 짧은 안내를 덧붙이자. 취소 버튼도 여기 있으면 좋다.
3. **응답 생성 중 취소 수단이 없다.** 30초짜리 턴을 잘못 보내면 끝날 때까지 입력이 잠긴다.

**P2 — 일관성**
4. **파괴적 동작의 확인 방식이 두 갈래다.** 메시지 삭제·기억 되돌리기·지시 삭제는 예쁜 인라인 확인인데, 시나리오·스토리·캐릭터 삭제는 브라우저 `window.confirm`이다. D7("모달 금지")에도 어긋난다. 인라인 확인으로 통일하자.
5. **(BUG-022) "10턴마다"가 고정 문구**라 설정을 바꾸면 거짓말이 된다.
6. **주인공 이름을 어디에 쓰는지 알 수 없다.** 이미지·키워드북·명령 탭에는 형식 안내가 있는데 주인공 탭에는 없다. 그래서 템플릿의 `- **이름**:` 줄을 지우고 자유롭게 쓰면 첫 메시지의 `{{user}}`가 조용히 "당신"이 되고 상태 패널 카드 제목도 "주인공"으로 남는다(실제로 겪었다). 주인공 탭에도 한 줄 안내를 넣고, 이름이 비면 편집 화면에서 알려 주자.

**P3 — 있으면 좋다**
7. **사용자 정의 명령 메시지가 일반 대사처럼 보인다.** `/일기`를 보내면 `kind=COMMAND`로 저장되는데 화면에서는 주인공이 "/일기"라고 말한 것처럼 보인다. 작은 칩(`명령`)을 붙이자.
8. **이어쓰기하면 직전 메시지의 후보를 못 고른다.** `‹ n/m ›`은 가장 최근 AI 메시지에만 붙는다. 이어쓴 뒤에는 애써 만든 후보 3개로 돌아갈 방법이 없다.
9. **넓은 화면에서 한 줄이 너무 길다.** 1280에서 말풍선이 `max-w-[85%]`라 한 줄 90자쯤 된다. 읽기 편한 폭(65~75자)으로 상한을 두자.
10. **선택 문서가 없을 때 콘솔에 404가 찍힌다.** 동작에는 문제가 없지만 실제 오류와 섞여 디버깅을 방해한다. 200 + 빈 내용으로 내리거나 프론트에서 조용히 넘기자.
11. **기록 이력 행이 `role="button"` 안에 버튼을 품고 있다.** 접근 이름이 행 전체 글자가 되어 스크린리더에서 "반영됨 턴 1–3 자동 … 되돌리기 버튼"으로 읽힌다. 행을 `div`로 두고 제목만 버튼으로 하자.

#### 다음 작업자에게
- 검증용 시나리오 **`T23검증`(스토리 2개: `T23 UI 검증`, `T23 분기 검증`)이 남아 있다.** 확인이 끝나면 UI에서 지우면 된다. `마도생존기`에 만든 스토리는 지웠고 T22의 것은 손대지 않았다.
- Playwright는 버전이 안 맞으면 `chromium_headless_shell-1187`을 직접 띄우고 `connectOverCDP`로 붙는 방식이 편하다. 단계별 스크립트가 세션을 이어 써서 CLI 호출을 아낄 수 있다.
- Playwright의 `getByRole('button', …)`은 `role="button"`인 `div`(기록 이력 행, 메시지 액션)까지 잡는다. 셀렉터가 애매해서 헛돈 적이 두 번 있었다. `exact: true`나 `locator('button', …)`를 쓰자.
- 브라우저의 `window.confirm`은 CDP로 붙었을 때 자동 닫힘과 경쟁한다. 삭제 흐름을 자동으로 확인하려면 `addInitScript`로 `window.confirm`을 대체하는 편이 확실하다(제안 4를 적용하면 이 문제도 사라진다).
