# T40 이미지 변형 — 상황 변형 지원, 예산 순서, 한 응답 상한

- **상태**: DONE
- **웨이브**: 8
- **의존**: T30(인라인 태그), T29(스토리 설정)
- **브랜치**: `task/T40-image-variant-fixes`
- **마이그레이션**: 없음
- **결정**: D42

## 배경
사용자가 물었다. "이미지가 여러 장인데 상황에 따라서도 넣을 수 있을까? `설월_키스`, `설월_대면좌위` 이런 식으로. 현재 상황으론 어떻게 돼?"

기술적으로는 됐다 — 변형 이름은 자유 문자열이다. 그런데 **세 가지가 걸렸다.**

## 고친 것

### 1. 프롬프트가 변형을 "감정"으로만 안내했다
T30의 문구가 이랬다.
> 변형은 **그 대사를 말하는 순간의 감정**에 가장 가까운 것을 고릅니다.

상황 변형이 목록에 있어도 모델이 감정어를 먼저 찾는다. 이렇게 바꿨다.
> **변형은 감정일 수도, 상황이나 자세일 수도 있습니다.** 괄호 안의 설명을 보고 **지금 장면에 맞는 것**을 고르세요. 감정어만 찾지 마세요.

같이 한 줄을 더했다 — **"같은 인물이라도 변형이 바뀌면 새로 넣습니다."** 자세가 바뀌는 장면에서 이미지가 갱신되게 하려면 필요하다.

### 2. 예산을 걸르기보다 먼저 잘랐다 (실질적 결함)
```kotlin
// 이전
val shown = entries.take(max)                                    // 파일 앞에서 50개를 먼저 자른다
val characterBlock = renderCharacters(shown, activeCharacters)   // 그 다음에 활성 인물로 걸른다
```
인물당 변형이 하나일 때는 문제가 없었다(무림천하 25명 = 25개). **인물당 상황 변형을 5개씩 넣으면 125개가 되고, `take(50)`이 파일 앞쪽 10명 분량만 남긴다.** 파일 뒤쪽 인물은 **활성이어도 변형이 하나도 프롬프트에 안 들어간다.**

**걸르기를 먼저 하고, 인물 변형이 예산을 먼저 쓰고 남은 것을 장면 태그가 쓰도록** 바꿨다. 인물 변형이 주 경로(D34)이므로 우선권을 준다.

### 3. 한 응답 상한이 코드에 박혀 있었다
`한 응답에 3개까지만`이 문구에 상수로 있었다. `crack.image.max-per-response`(기본 3)로 빼고, 스토리별 `settings.json`의 `maxCharacterImages`(0~20)가 이기게 했다. 상황 변형을 쓰면 한 장면에서 여러 번 바뀌므로 3장이 좁다.

## 작업 로그

### 2026-09-28
**2번이 진짜 버그였다.** 1번과 3번은 새 쓰임새(상황 변형)를 위한 조정이지만, 2번은 **이미 있던 결함**이다. 지금은 인물당 변형이 하나뿐이라 드러나지 않았을 뿐, 변형을 늘리는 순간 조용히 이미지가 사라진다. 상황 변형과 무관하게 고쳐야 했다.

**예산을 블록마다 따로 주지 않았다.** 각 블록에 `take(max)`를 걸면 총합이 2배가 될 수 있다. 설정 이름이 "프롬프트에 넣는 태그 수 상한"이므로 **하나의 예산을 인물 → 장면 순서로 쓰는** 쪽을 택했다.

**확인:** 573개 통과. 새 테스트 5개 중 둘이 핵심이다 — 「예산은 걸른 뒤에 쓴다」(비활성 인물 변형 10개를 앞에 두고 활성 인물을 맨 뒤에 둔 뒤 `max=5`로 검사), 「인물 변형이 예산을 먼저 쓰고 남은 것을 장면 태그가 쓴다」.
