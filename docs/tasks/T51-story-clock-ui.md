## 구현 내용
- **시각이나 장소가 바뀐 메시지 위에만** 그린다. 매 턴 그리면 소설 흐름이 끊긴다
- **턴 번호만 바뀌고 시각·장소가 같은 턴에는 그리지 않는다.** 턴 번호 때문에 매 턴 그리게 되면 안 된다

- 소설 모드(T31)에서는 **턴 구분선(T32) 자리를 대신한다.** 머리글이 있는 자리에 선을 또 그리지 않는다
- 시각·장소가 없는 메시지(옛 스토리, 시계를 끈 시나리오)에는 아무것도 그리지 않는다

**내린 설계 판단과 이유**

1. **시각은 보여 주되, 다시 그릴지는 날짜와 장소로만 정한다.** 이게 이 작업의 핵심 판단이다.
   - AI는 태그 규칙에 따라 **매 턴** `[시간: …]`을 적고, T38 실검증에 따르면 **대화 한 마디에 1분**씩 흘려 놓는다. 분까지 비교하면 머리글이 매 턴 떠서 소설 흐름이 끊긴다 — 명세가 명시적으로 막은 실패다.
   - 그래서 열쇠는 `날짜 + 장소`다. 머리글의 시각은 **그 장면이 시작한 시각**으로 읽힌다(소설의 장면 머리글과 같다). 실측대로 분이 천천히 흐르는 동안에는 머리글이 그대로 있고, 날이 가거나 자리를 옮기면 새 머리글이 뜬다.
   - 처음에는 명세 예시(`T47 · 2026. 09. 26. 수요일. 에미야 저택`) 그대로 시각을 빼고 도움말로만 두려 했다. **T38 실검증 로그를 보고 넣는 쪽으로 바꿨다** — 실제 플레이에서 장면이 바뀔 때 `14:21 → 15:30 → 23:20`처럼 시각이 크게 뛴다. 머리글은 이 시계를 사용자가 보는 **유일한 자리**이므로, 여기서 빼면 T38이 저장한 값이 화면에 한 번도 나오지 않는다.
   - 시각을 다시 빼고 싶으면 `StoryClockHeader`의 span 하나와 `storyClockLine` 한 줄이면 된다. 반대로 머리글을 더 자주 띄우고 싶으면 `headerOf`의 `key`만 고치면 된다.
2. **요일은 로케일 API에 맡기지 않는다.** `toLocaleDateString('ko-KR', …)`은 브라우저·OS 설정에 따라 결과가 흔들린다. 요일 이름 배열을 직접 두고 UTC 자정으로 만든 날짜의 `getUTCDay()`로 뽑는다.
3. **`new Date(문자열)`로 해석하지 않는다.** 서버가 보내는 값은 시간대가 없는 지역 시각이라 브라우저가 UTC로 읽으면 날짜가 하루 밀 수 있다. 정규식으로 숫자만 뽑고, 요일 계산에만 `Date`를 쓴다(UTC 자정끼리 비교하므로 시간대와 무관하다). 연도 0~99도 `setUTCFullYear`로 제대로 다룬다(`Date.UTC`는 1900년대로 옮긴다).
4. **값이 있는 메시지끼리만 비교한다.** USER 메시지는 시각·장소가 언제나 `null`이므로, `null`인 메시지는 결과를 `null`로 두되 **직전 값을 갱신하지 않는다.** USER 메시지가 끼어도 ASSISTANT끼리 비교된다.
5. **머리글과 턴 구분선 중 하나만 그린다.** `TurnBreak`가 둘 중 하나를 고른다. 머리글이 있으면 선을 그리지 않는다(명세의 "자리를 대신한다"). 머리글이 없으면 예전 그대로다 — 시계를 쓰지 않는 스토리의 화면은 **한 픽셀도 달라지지 않는다.**
6. **좁은 화면 대책은 "글이 줄바꿈되게" 하는 것이다.** 머리글을 통짜 문자열 하나로 그리면 내용만큼 폭을 차지해 화면 끝에서 잘린다(T36 회귀). 조각마다 `span`을 두고 `flex-wrap`으로 감쌌다. 말풍선형 칩에는 `max-w-full`, 소설형 좌우 선에는 `flex-1 min-w-4`를 줘서 선이 먼저 줄고 글에 자리를 내준다.
7. **스트리밍 중에는 머리글을 새로 그리지 않는다.** 스트림에는 아직 `storyTime`이 없다(서버가 `done`에서 준다). 제자리 재생성 중에는 원래 메시지의 머리글이 그대로 있다가 `done`이 오면 맞춰진다.

**확인한 방법**

- `cd crack-frontend && npm ci && npm run build && npm run lint` → **build 통과, lint 오류 0**.
- **순수 함수 눈 검증**: `storyClock.ts`를 `tsc`로 뽑아 node로 돌려 값을 찍어 봤다(스크래치 경로, 저장소에는 남기지 않았다).
  - 파싱: 초 있음/없음 둘 다 받음, `null`·`'나중에'`·`2026-02-31`·`25:00`은 `null`, `0050-03-01` → `화요일`.
  - 요일: `2026-09-26 토`, `2026-09-30 수`, `2026-02-15 일`, `2024-02-29 목`, `1999-12-31 금` — 전부 맞다.
  - 자리: 프롤로그(turn 0) 머리글 뜸 → USER `null` → **분만 바뀐 턴 안 뜸** → 장소 바뀐 턴 뜸 → 날짜 바뀐 턴 뜸 → 같은 날·같은 장소 안 뜸 → 장소만 바뀐 턴 뜸. 시계 없는 스토리는 전부 `null`.
  - **명세 예시(`2026. 09. 26. 수요일`)의 요일은 실제와 다르다** — 2026-09-26은 토요일이다. 요일을 값으로 계산해야 하는 이유를 그대로 보여 주는 예다. 화면에는 계산한 요일이 나간다.
- **좁은 화면**: 빌드된 CSS를 그대로 쓰는 정적 HTML에 두 모드의 실제 마크업을 넣고 헤드리스 크롬으로 **360px·320px 기둥**을 재서 스크린샷을 찍었다. 두 폭 모두 `scrollWidth == clientWidth`이고 **기둥 밖으로 나간 요소 0개**다(짧은 장소와 "후유키 시립 중앙병원 3층 특별 병동 복도 끝 창가" 같은 긴 장소 둘 다). 긴 장소는 두 줄로 접히고 소설형 좌우 선이 짧아지며 버틴다.
- **T38 실검증 로그의 실제 플레이 값을 그대로 넣어 돌려 봤다** (`14:21 응접실 → 10-02 15:30 별채 → 23:20 저택`). 세 턴 모두 장면이 실제로 바뀐 턴이라 머리글이 셋 다 떴고, USER 메시지와 시각 없는 프롤로그에는 아무것도 뜨지 않았다.
- **같은 장면에서 대화만 이어지는 8턴**(분만 1씩 흐름)을 넣으면 머리글은 **첫 턴 하나만** 뜬다. 이것이 "매 턴 뜨지 않는다"의 실제 증거다.
- 실제 플레이 확인은 하지 않았다(서버를 띄우지 않았다). **눈으로 볼 곳은 아래 "다음 작업자가 알아야 할 것"에 적었다.**

**다음 작업자가 알아야 할 것**

- **머리글 빈도는 장소 표기에 달렸다.** 날짜+장소 기준이면 하루가 가거나 자리를 옮길 때만 뜬다. 다만 T38 실검증에서 AI는 같은 저택을 `쿠로세 저택 응접실` → `쿠로세 저택 별채` → `쿠로세 저택`으로 적었다 — **표기가 조금만 달라져도 새 머리글이 뜬다.** 그 세 턴은 실제로 장면이 바뀐 턴이라 문제가 아니었지만, 한 장면 안에서 표기만 흔들리면 잦아질 수 있다. 잦으면 열쇠에서 장소를 빼거나(날짜만) 장소를 정규화하는 쪽을 보면 된다 — 고칠 곳은 `storyClock.ts`의 `headerOf` 한 곳이다.
- 프론트에는 여전히 테스트 프레임워크가 없다. 그래서 판단 로직을 전부 `storyClock.ts`(순수 함수, React 의존 없음)에 몰아 뒀다 — 테스트가 생기면 이 파일이 첫 대상이다.
- `emotionTag.ts`(화면쪽 방어용 태그 숨김)에는 `시간`·`장소`를 넣지 않았다. 서버 `EmotionTagFilter`가 스트림에서 이미 떼고 보내므로 필요가 없고, T51의 범위도 아니다. 만약 옛 메시지에서 `[시간: …]`이 본문에 보이면 그때 넣으면 된다.
- 시계 머리글은 `settings.json`에 `clock`을 적은 스토리에서만 보인다(§5.4). 옛 스토리 화면은 그대로다.
