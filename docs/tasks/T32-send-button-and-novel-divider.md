## 목표
두 가지를 고친다.
1. **Enter로 전송되는 것을 막는다.** Enter는 줄바꿈이고, 전송은 전송 버튼으로만 한다
2. **소설형에서 사용자 입력 구분을 바꾼다.** 왼쪽 강조선(마크다운 인용 `>`처럼 보인다)을 버리고, 턴 사이 **가로 구분선(`---`)**으로 나눈다

## 구현 내용

### 1. Enter 전송 제거
- `handleKeyDown`에서 `Enter && !shiftKey → submit()` 분기를 없앤다. Enter는 textarea 기본 동작(줄바꿈)이 된다
- **명령 자동완성의 Enter도 전송으로 이어지지 않는다.** 전에는 이름을 다 입력한 상태(`/기록` + Enter)에서 아래로 떨어져 전송됐다. 이제 그 경우 목록만 닫는다
- placeholder `메시지 · 빈 Enter: 이어쓰기` → `메시지 · 빈 칸으로 전송: 이어쓰기`
- 이어쓰기는 그대로다. 입력이 비어 있을 때 전송 버튼을 누르면 이어쓰기가 된다(버튼 아이콘도 이미 그때 바뀐다)

### 2. 턴 구분선
- `MessageList`에 `TurnDivider`(`<hr>`)를 두고, 소설형에서 **첫 턴을 제외한 모든 턴 위에** 넣는다. 스트리밍 중인 응답과 보내는 중인 사용자 입력 앞에도 넣는다
- `ChatBubble`의 소설형 사용자 스타일에서 `border-l-2`, `pl-3.5`, `text-text-secondary`를 없앤다. **사용자와 AI를 글자 모양으로 구분하지 않는다**

## 작업 로그

### 2026-09-27
사용자가 폰으로 플레이하다 두 가지를 지적했다. "엔터만 쳐도 바로 송신된다. 무조건 버튼으로 송신하게 해줘." / "사용자의 말과 AI 출력 구분할 때 MD 파일 형식의 `>` 이거 말고 `---`로 단락을 나눠서 구분해."

**Enter 전송은 채팅 앱의 관습이다.** 이 앱은 한 턴이 여러 줄인 산문을 쓰는 곳이라 줄바꿈이 전송보다 훨씬 자주 필요하다. Shift+Enter로 줄바꿈하는 방식은 손이 하나 더 가고, 한글 조합 확정용 Enter가 전송으로 새는 사고를 완전히 막지 못한다(T18 당시 `isComposing` 가드를 넣었지만 빈 입력 이어쓰기로 새는 경우가 남아 있었다). **Enter를 줄바꿈으로 되돌리고 전송을 버튼으로 몰았다.**

**명령 자동완성 쪽에 빠진 길이 있었다.** `/기록`처럼 이름을 다 입력한 상태의 Enter는 팔레트 분기를 통과해 아래 `submit()`으로 떨어지게 되어 있었다. Enter 전송만 지우면 이 경로가 아무 일도 안 하면서 줄바꿈이 들어가는 어정쩡한 상태가 된다. 그 경우 **목록만 닫도록** 명시했다.

**왼쪽 세로선이 인용처럼 보인다는 지적이 맞다.** T31에서 사용자 입력을 `border-l-2 border-accent/50`으로 구분했는데, 이건 마크다운 인용(`>`)의 시각 관습이다. 본문이 "어딘가에서 인용된 글"로 읽힌다. **가로 구분선은 소설의 장면 전환 기호와 같은 관습**이라 같은 일을 하면서 흐름을 깨지 않는다.

**글자색으로도 구분하지 않게 했다.** 구분선이 턴을 나누므로 색까지 다르게 할 이유가 없다. 이제 소설형에서 사용자 입력과 AI 응답은 완전히 같은 활자로 나오고, 사이에 선만 있다.

**확인:** 프론트 build·lint 통과. 폰과 데스크톱에서 Enter 줄바꿈, 버튼 전송, 빈 입력 이어쓰기, `/명령` + Enter, 구분선 위치(첫 턴 위 없음)를 확인했다.

**다음 작업자에게:**
- 전송 단축키를 다시 넣을 거면 Enter가 아니라 `Cmd/Ctrl+Enter`로 넣는다. 조합 확정용 Enter와 부딪히지 않는다
- 구분선은 소설형에서만 나온다. 말풍선 모드는 T31 이전과 같다
