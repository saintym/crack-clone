# T27 인물 이미지 자동 삽입 + 카탈로그 등록 UX

- **상태**: DONE
- **웨이브**: 8
- **의존**: 없음 (T24와 병렬 가능. 단 `prompt/contributor` 파일이 겹치면 T24를 먼저 머지)
- **브랜치**: `task/T27-image-auto-insert`
- **마이그레이션**: **V8**
- **결정**: D14, D19, D31

## 목표
지금은 AI가 스스로 `{{img:태그}}`를 쓴 턴에만 이미지가 나온다(실측 7턴 중 3턴). 사용자는 **인물이 등장하는 거의 모든 턴에 이미지가 나오기를** 원한다. 서버가 화자와 감정으로 이미지를 결정적으로 고르게 만들고, URL 등록을 쉽게 한다.

## 범위
- `chat/flow/EmotionTagFilter`(또는 인접 파일): 첫 줄 태그 파싱을 `[감정: …]` + `[인물: …]`로 확장
- `message/**`: `speaker` 칼럼 추가(V8), `MessageView`에 `speaker`·`emotion` 노출
- `prompt/contributor/BaseContributor`: 출력 형식에 인물 태그 추가
- `image/**`: 카탈로그 조회에 태그 규칙 헬퍼 추가
- 프론트: `ChatBubble`(이미지 선택·표시), `api/chat.ts` 타입, `components/scenario/ImageCatalogList.tsx`(등록 UX)
- `data/_templates/images.md`, `docs/DESIGN.md` §5.3·§8.5, 관련 테스트

## 구현 내용

### 1. 화자 태그 (`[인물: 이름/변형]`) — AI가 카탈로그 목록에서 고른다 (D31)
- 감정 태그와 같은 방식이다. AI는 응답 첫 줄에 `[감정: 슬픔] [인물: 설월/당황]`처럼 쓰고, **서버가 떼어 내 저장한다. 사용자에게는 절대 보이지 않는다**(D19와 동일).
- **변형은 프롬프트에 준 목록 안에서 고르게 한다.** 카탈로그에 `설월_기본`, `설월_당황`, `설월_분노`만 있으면 슬픔이든 행복이든 그 셋 중 가장 가까운 것을 고른다. 감정 태그(`[감정: …]`)는 지금처럼 자유롭게 쓴다. 둘은 별개다.
- 변형 없이 `[인물: 설월]`만 써도 되고(→ `설월_기본`), 인물이 없거나 주인공만 나오면 태그를 생략한다. 중심 인물 한 명만 쓴다.
- 저장: `story_messages.speaker`, `speaker_variant` / `message_variants.speaker`, `speaker_variant` (V8, VARCHAR(100)·VARCHAR(50), NULL 허용). 후보마다 따로 저장한다.

### 2. 서버가 고르지 않고 **프론트가 렌더 시 고른다**
`{{img:태그}}`를 본문에 끼워 넣지 않는다. 본문은 순수 텍스트로 두고, 프론트가 `speaker` + `emotion`으로 카탈로그에서 골라 말풍선 위에 표시한다.
- 이유: ① 카탈로그를 나중에 바꾸면 과거 메시지에도 바로 반영된다 ② 본문이 오염되지 않아 수정·내보내기·기억 기록이 깨끗하다 ③ 이미지가 없을 때 빈 줄이 남지 않는다
- 선택 순서: `{speaker}_{speakerVariant}` → `{speaker}_기본` → 없으면 표시하지 않는다. AI가 목록에 없는 변형을 골라도 폴백이 받아 준다
- **AI가 본문에 직접 쓴 `{{img:태그}}`가 있으면 그게 우선이고, 자동 선택은 하지 않는다**(장면 이미지 등 의도적 삽입)
- 프롤로그(사람이 쓴 첫 메시지)에도 같은 규칙을 적용한다

### 3. 프롬프트
- BASE 출력 형식에 인물 태그 규칙을 넣는다(형식 `[인물: 이름/변형]`, 한 명만, 없으면 생략, 변형은 **주어진 목록 안에서만**)
- `ImagesContributor`를 바꾼다
  - **활성 인물별로 쓸 수 있는 변형 목록**을 준다. 예: `설월 — 기본, 당황, 분노`. 활성 인물 선택은 `ActiveCharacterSelector`(T13)를 재사용한다. 카탈로그에 항목이 없는 인물은 목록에서 뺀다
  - 장면·배경 태그(`인물_`으로 시작하지 않는 것)는 지금처럼 "필요할 때만 `{{img:태그}}`로 본문에 직접" 안내한다
  - 활성 인물은 기록 회차 동안 고정되므로(D30) 이 목록도 회차 안에서 바뀌지 않는다. 캐시 접두사가 깨지지 않는다

### 4. 카탈로그 등록 UX (시나리오 상세 "이미지" 탭)
지금은 마크다운을 직접 쓴다. 마도생존기는 인물이 24명이라 이대로는 채우기 어렵다.
- **인물 목록 기반 편집기**: 시나리오의 인물 목록을 보여 주고, 각 인물 행에 URL을 붙여 넣으면 `인물_기본` 항목이 만들어진다
- 인물마다 "감정 추가" → `인물_미소`처럼 변형을 더한다. 감정 이름은 자유 입력
- 썸네일 미리보기, 불러오기 실패·형식 오류 표시(기존 기능 유지)
- 저장은 기존 `images.md` 그대로다(형식 변경 없음). 사용자가 마크다운을 직접 고치는 길도 남긴다
- **업로드 기능은 만들지 않는다.** 이미지는 사용자가 앱 밖에 올리고 URL만 붙여 넣는다(D14)

### 2026-09-25 구현

#### 한 일
1. **인물 태그 저장 (V8)** — `story_messages`·`message_variants`에 `speaker`(VARCHAR 100), `speaker_variant`(VARCHAR 50). 후보마다 따로 저장하고, 후보를 고르면 메시지 쪽 값도 같이 동기화한다. 분기 복사에도 넣었다.
2. **첫 줄 태그 파싱 확장** — `EmotionTagFilter`가 `[감정: …]`과 `[인물: 이름/변형]`을 **앞에서부터 연달아** 소비한다. 한 줄에 같이 써도, 두 줄로 나눠 써도, 태그 뒤에 본문이 붙어 있어도 태그만 뗀다. `ResponseTags(emotion, speaker, speakerVariant)`로 묶어 `MessageService`까지 넘긴다.
3. **프롬프트** — BASE 출력 형식에 인물 태그 규칙 추가. `ImagesContributor`를 ①활성 인물 변형 목록 ②장면·배경 태그(`{{img:}}`) 두 블록으로 나눴다. 인물 이미지는 장면 태그 목록에서 **뺐다**(AI가 본문에 직접 넣으면 자동 선택이 꺼지므로).
4. **프론트 자동 표시** — `ChatBubble`이 렌더 시 `speaker`로 카탈로그에서 고른다(`{인물}_{변형}` → `{인물}_기본` → 없으면 표시 안 함). 본문에 카탈로그에 있는 `{{img:…}}`가 있으면 자동 선택을 하지 않는다.
5. **등록 화면** — `ImageCatalogEditor`(인물 목록 기반). 인물마다 `기본` 줄이 항상 보이고 주소만 붙여 넣으면 등록된다. 변형·장면 태그 추가와 삭제, 썸네일, 형식 오류 줄 표시. 마크다운 직접 편집 경로는 그대로 남겼다.

#### 설계 판단
- **태그 줄이 아니라 "앞쪽 태그들"을 소비한다.** 예전에는 첫 줄 전체가 `[감정: …]` 형식일 때만 뗐고, `[감정: 기쁨] 본문…`처럼 섞이면 통째로 흘렸다(옛 테스트가 그 동작을 고정하고 있었다). 인물 태그까지 늘어나면 형식이 어긋날 확률이 커지고, **태그가 한 글자라도 새면 몰입이 깨지므로** 앞에서부터 태그만 떼고 나머지는 본문으로 남기게 바꿨다. 상한은 태그 4개·2줄·값 200자다(닫히지 않은 대괄호로 스트림이 막히지 않게).
- **`MessageView`에 `emotion`도 같이 노출한다**(§5.2 계약 변경). 인물 이미지 선택에는 `speaker`만 쓰지만, 화면이 쓸 수 있는 내부 신호를 한 벌로 맞춰 두는 편이 낫다고 봤다. 글로 출력하지 않는다는 규칙은 그대로다.
- **인물 이미지를 장면 태그 목록에서 뺐다.** 명세의 "인물_으로 시작하지 않는 것"을 인물 문서 이름 기준으로 판정한다(`characters/{이름}.md`의 이름 + `_`). 그래야 AI가 `{{img:설월_미소}}`를 본문에 직접 써서 자동 선택을 꺼 버리는 일이 없다.
- **본문 태그 우선 조건은 "카탈로그에 있는 태그가 있을 때"로 좁혔다.** AI가 카탈로그에 없는 태그를 지어내면 아무 이미지도 안 나오는 대신 인물 이미지로 폴백한다.
- **프롤로그도 같은 규칙으로 파싱한다**(`PrologueService`, 범위 밖 최소 수정). 사람이 `prologue.md` 첫 줄에 `[인물: 설월/기본]`을 적어 두면 첫 메시지부터 이미지가 붙는다. 덤으로 BUG-023(사용자가 쓴 감정 태그가 `content`에 남던 문제)이 새 스토리에서는 사라진다.
- **등록 화면은 `images.md` 텍스트를 줄 단위로 고친다.** 항목 목록에서 파일을 다시 만들어 쓰면 주석(템플릿 안내문)과 인식하지 못한 줄이 날아간다. 있으면 그 줄 교체, 없으면 파일 끝에 추가, 지우면 그 줄만 삭제. 주석 안의 줄은 건드리지 않는다.
- **저장은 요청 순서대로 보낸다.** 여러 줄을 빠르게 채울 때 앞선 PUT의 결과를 기다리지 않고 다음 변경을 만들면 항목이 유실된다. 편집기가 현재 텍스트를 state로 들고(부모가 새로 읽어 오면 렌더 중 동기화) 저장은 프라미스 체인으로 직렬화했다. 24줄을 4초에 채워도 유실이 없다.
