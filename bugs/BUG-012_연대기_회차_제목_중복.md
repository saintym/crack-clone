# BUG-012: 회차 제목까지 써 보낸 `<revised>`·`<chronicle>`이 연대기에 제목 줄을 중복 생성

## 상태: 수정완료 (T22, 2026-09-24)
## 심각도: 중간

## 증상
실제 Claude Code CLI로 기억 기록을 돌리다 발견했다. 수정된 과거 턴을 재반영하는 `<revised entry="1">` 출력에 모델이 회차 제목 줄까지 넣어 보냈고, 그 본문이 그대로 반영되어 `chronicle.md`가 이렇게 됐다.

```markdown
## 회차 1 (턴 1–3)
## 회차 1 (턴 1–3)
- 밤, 눈보라 속 움막 문 앞에 …
```

같은 번호의 회차가 두 개(앞은 본문이 빈 회차)가 되므로 뒤따르는 동작이 어긋난다.
- `Chronicle.entries()`가 회차 1을 두 번 읽는다.
- 다음 재반영(`reviseEntry`)과 압축(`replaceOldestWithSummary`)은 제목으로 섹션을 찾으므로 **본문이 빈 앞쪽 회차를 고치고**, 실제 본문은 손대지 못한다.
- 프롬프트(SCENARIO 슬롯)에 제목 줄이 두 번 실린다.

`<memory>`, `<changes>`, `<compressed>`는 `RecordOutputParser.stripHeading`으로 제목 줄을 떼고 있었는데, 회차 제목은 `회차 2 (턴 4–6)`처럼 값이 달라져 고정 문자열과 비교할 수 없어 빠져 있었다. `<chronicle>`도 같은 구멍이 있었다.

## 재현
`memory/record/RecordPrompts.kt`의 시나리오 관리자 프롬프트는 "`#` 제목 줄은 쓰지 않는다"라고 지시하지만, 모델이 항상 지키지는 않는다(같은 프롬프트로 한 번은 지켰고 한 번은 어겼다). 파서가 방어하지 않으면 그대로 파일에 들어간다.

## 수정 (T22)
- `RecordOutputParser.stripEntryHeading(body)`: 본문 맨 앞이 `#{1,6} 회차 N …` 제목 줄이면 뗀다. `<chronicle>`과 모든 `<revised entry="N">` 본문에 적용한다.
- 제목 줄만 오고 본문이 없으면 빈 본문으로 보고 기존 규칙대로 `RecordFormatException`이 난다(기록은 재시도 후 FAILED가 되고, 파일은 하나도 쓰이지 않는다).
- 회귀 테스트 `RecordOutputParserTest` 3개: 제목 줄 제거, 회차 제목이 아닌 제목(`## 장 요약`)·글머리표는 그대로 둠, 제목만 온 경우 실패.

## 남은 것
이미 제목이 중복된 `chronicle.md`를 자동으로 고치지는 않는다(이번 검증 스토리는 되돌리기로 정리했다). 실데이터에서 발견되면 파일을 직접 손보면 된다.
