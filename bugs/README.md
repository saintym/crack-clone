## 패턴 분석

### 공통 원인: 프론트-백엔드 계약 불일치 (BUG-001~003)
프론트엔드 코드를 작성할 때 백엔드 DTO/API 스펙을 직접 확인하지 않고 추정으로 작성하여 발생.

### PG 방언 문제 (BUG-008)
테스트가 H2로만 돌아 PostgreSQL에서만 실패하는 쿼리가 머지됐다. T21에서 JPQL의 "파라미터 IS NULL" 패턴을 금지하는 검사 테스트를 넣었다. 근본 대책(테스트에 실제 PG 도입, Testcontainers 등)은 후속 과제다.

### LLM 출력 방어 부족 (BUG-012)
프롬프트로 "제목 줄을 쓰지 말라"고 지시해도 모델이 늘 지키지는 않는다. 실제 AI로 돌려 보니 같은 프롬프트가 한 번은 지키고 한 번은 어겼다. **파서가 형식을 방어**해야 한다(제목 줄 제거, 코드 펜스 제거처럼). 실제 모델 없이 Fake 응답으로만 검증하면 이 유형은 절대 드러나지 않는다.
### 실패 경로를 안 밟아 봤다 (BUG-020, BUG-021)
성공 경로만 확인해서 살아남은 버그들이다. 로그인은 "맞는 비밀번호로 들어가진다"까지만 봤고
(BUG-020), 인증은 "토큰이 있으면 통과"까지만 구현됐다(BUG-021). 화면을 만들 때
**틀린 입력·만료·위조**를 한 번씩 밟아 보는 것을 확인 절차에 넣는다.

### CSS cascade layer (BUG-010)
Tailwind v4는 유틸리티를 `@layer utilities`에 넣는다. 레이어 밖의 규칙은 명시도와 무관하게 레이어 안 규칙을 이기므로, `index.css`에 직접 쓰는 전역 규칙은 `@layer base`나 `@layer components`에 둔다.
