# BUG-005: 시나리오 데이터 경로 불일치

## 상태: 수정완료 (T02, 2026-09-23)

## 증상
기존 "테스트세계" 시나리오의 문서(world.md 등) 조회 시 404 에러

## 원인
- 기존 시나리오의 DB `dataPath`: `./data/테스트세계` (상대경로, crack-backend 기준)
- `application.yml`의 `crack.data-path`: `../data` (crack-backend 기준 → crack-clone/data/)
- `DocumentService`는 `dataPathConfig.dataPath`를 사용하여 경로를 조립
- 결과적으로 `../data/테스트세계/world.md`를 찾지만 실제 파일은 `./data/테스트세계/world.md`에 존재

## 근본 원인
경로를 두 군데서 따로 계산했다. DB에는 생성 당시의 `data-path`로 조립한 경로(`scenarios.data_path`, `stories.data_path`)가 박제되어 있었고, `DocumentService`는 현재 설정값으로 경로를 새로 조립했다. `data-path` 설정을 바꾸자(`./data` → `../data`) 두 값이 어긋났다.

## 임시 조치 (당시)
`crack-backend/data/테스트세계/`를 `crack-clone/data/테스트세계/`로 복사

## 근본 수정 (T02)
DB에 경로를 저장하지 않는다. 경로는 항상 `crack.data-path` + 시나리오 `name` + 스토리 `dir_name`으로 계산한다 (DESIGN.md §1).

1. **`DataPaths` 컴포넌트** (`global/config/DataPaths.kt`)가 경로 계산의 유일한 진입점이다.
   - 루트는 `Path.of(crack.data-path).toAbsolutePath().normalize()`로 한 번만 계산한다. 상대 경로는 백엔드 프로세스의 작업 디렉터리 기준이다.
   - `scenarioDir(name)` = `{root}/{name}`, `storyDir(name, dirName)` = `{root}/{name}/stories/{dirName}`, `templatesDir()` = `{root}/_templates`
   - `dirName == "_legacy"`이면 시나리오 폴더 자체를 가리킨다(옛 기본 스토리). 폴더 이전은 T09가 한다.
   - 이름은 경로 조각 하나만 허용한다(`/`, `\`, `.`, `..`, 빈 값 거부 → 400). 데이터 루트 밖으로 나가는 경로를 막는다.
2. **엔티티**: `Scenario.dataPath`, `Story.dataPath` 제거, `Story.dirName` 추가. `ScenarioResponse.dataPath`도 제거했다.
3. **V4 마이그레이션** (`V4__relative_paths.sql`)
   - `stories.dir_name` 추가 → 기존 `data_path`가 `.../stories/{dir}` 형태면 `{dir}`, 아니면 `'_legacy'`
   - `NOT NULL` 설정 후 `scenarios.data_path`, `stories.data_path` 삭제
4. `_legacy` 스토리를 삭제할 때는 시나리오 폴더를 지우지 않고 DB 레코드만 지운다.

이제 `data-path`를 바꿔도 DB는 그대로이고, 새 위치에 같은 폴더 구조만 있으면 된다.

### 검증
- 단위 테스트 `DataPathsTest`: 상대·절대 `data-path`, 정규화, `_legacy`, 설정 변경, 잘못된 이름 거부
- `StoryServiceTest`: 생성·분기 폴더 위치, `_legacy` 삭제 시 시나리오 폴더 보존
- 임시 PostgreSQL 14에서 V1~V4 적용 후 `dir_name` 값 확인(절대·상대·끝 슬래시·Windows 구분자·옛 기본 스토리), 앱을 Flyway + `ddl-auto: validate`로 기동해 엔티티와 스키마 일치 확인

## 남은 정리: `crack-backend/data/` 임시 복사본
`crack-backend/data/`는 옛 기본값(`./data`) 시절의 원본이고 사용자 데이터라서 **코드에서 건드리지 않았다.** V4 이후에는 어떤 코드도 이 폴더를 읽지 않는다(`crack.data-path: ../data` 기준). 직접 정리하려면:

1. 백엔드를 멈춘다.
2. 두 폴더를 비교한다: `diff -rq crack-backend/data/테스트세계 data/테스트세계`
   - 2026-09-23 기준 `chat/chat_latest.md`가 서로 다르다. 필요한 대화가 `crack-backend/data/` 쪽에만 있으면 `data/` 쪽으로 옮긴다.
3. 차이가 정리되면 백업 후 삭제한다: `mv crack-backend/data ~/crack-data-backup-YYYYMMDD` (확인 후 삭제)
4. 백엔드를 다시 띄우고 시나리오 문서와 스토리 대화가 열리는지 확인한다.
