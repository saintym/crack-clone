# BUG-021: 토큰을 검증하지 않아 아무 문자열로 비밀번호를 우회할 수 있다

## 상태: 미수정 (2026-09-24 등록, T23)
## 심각도: 높음(보안) — 비밀번호를 모르는 사람이 모든 API를 쓸 수 있다

## 증상
`Authorization: Bearer` 뒤에 **10자보다 긴 아무 문자열**을 붙이면 인증을 통과한다.
비밀번호는 전혀 필요 없다.

```
$ curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8082/api/scenarios
401
$ curl -s -o /dev/null -w "%{http_code}\n" \
    -H "Authorization: Bearer invalid.token.value" http://localhost:8082/api/scenarios
200            ← 시나리오 목록 전체가 그대로 내려온다
$ curl -s -o /dev/null -w "%{http_code}\n" \
    -H "Authorization: Bearer aaa.bbb.ccc" http://localhost:8082/api/scenarios
200
```

브라우저에서도 `localStorage['crack-token'] = 'invalid.token.value'`로 바꾸고 새로고침하면
로그인 화면으로 가지 않고 시나리오 목록이 그대로 뜬다.

## 원인
`crack-backend/src/main/kotlin/com/crack/global/auth/AuthFilter.kt`가 토큰의 **길이만** 본다.

```kotlin
val token = auth?.removePrefix("Bearer ")?.trim()
if (token == null || token.length <= 10) { 401 }
filterChain.doFilter(request, response)   // 그 외에는 전부 통과
```

`AuthController.isValidToken`도 같다 (`token.isNotBlank() && token.length > 10`),
주석에도 `Simple: any non-empty token is valid (stateless, password is the gate)`라고 적혀 있다.

발급 토큰은 `Base64Url(SHA-256("$tokenSecret:${currentTimeMillis()}"))`라서, 서버가 저장하지도
서명하지도 않아 **검증할 수 있는 정보가 애초에 없다.** 길이 검사는 그 자리를 메운 임시방편이다.

## 영향
- `vite.config.ts`가 `allowedHosts: true`, `host: '0.0.0.0'`이고 저장소도 공개다.
  집 밖에서 접근할 수 있게 열어 두면 비밀번호는 사실상 없는 것과 같다.
- 시나리오·스토리 읽기뿐 아니라 삭제(`DELETE /api/scenarios/{name}`)까지 전부 열린다.

## 고칠 방향 (제안)
토큰을 **검증 가능하게** 만든다. 서버 상태를 두지 않으려면 만료 시각을 붙여 HMAC으로 서명한다.

```
token = base64url(expEpochSec) + "." + base64url(HMAC_SHA256(tokenSecret, expEpochSec))
```
- 발급: `AuthController.login`이 위 형식으로 만든다
- 검증: `AuthFilter`와 `/api/auth/verify`가 서명과 만료를 확인한다(`MessageDigest.isEqual`로 상수 시간 비교)
- `crack.auth.token-secret` 기본값 `crack-default-secret-change-me`를 쓰고 있으면 기동 시 경고를 남긴다

## 범위
백엔드 작업이라 T23(브라우저 UI 검증)에서는 고치지 않았다. 별도 작업으로 다룬다.
