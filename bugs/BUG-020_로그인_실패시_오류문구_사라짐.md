# BUG-020: 비밀번호를 틀리면 오류 문구 없이 입력칸만 비워진다

## 상태: 수정완료 (2026-09-24, T23)
## 심각도: 중간 — 로그인이 왜 안 되는지 알 수 없다. 앱의 첫 화면에서 일어난다

## 증상
로그인 화면에서 틀린 비밀번호로 로그인하면
- `비밀번호가 올바르지 않습니다` 문구가 **뜨지 않는다**
- 입력칸의 내용이 사라진다
- 아무 일도 없었던 것처럼 빈 로그인 화면이 다시 보인다

브라우저 확인(1280 폭, headless Chromium)에서 `POST /api/auth/login` 401 직후
`.text-danger` 요소 개수 0, `input[type=password]` 값 빈 문자열을 확인했다.

## 원인
`crack-frontend/src/api/client.ts`의 응답 인터셉터가 **모든** 401에 대해
`window.location.href = '/login'`을 실행했다.

```ts
if (err.response?.status === 401) {
  localStorage.removeItem('crack-token');
  window.location.href = '/login';   // 로그인 요청의 401까지 여기로 온다
}
```

로그인 요청이 401이면 이 줄이 페이지를 통째로 새로 띄운다. `LoginPage`가 다시 마운트되므로
`catch` 블록이 세운 `setError(...)`와 입력값이 그대로 날아간다. 즉 오류 문구를 만들긴 하는데
그리기 전에 페이지가 새로 뜬다.

## 발견
T23 브라우저 UI 실검증, 확인 항목 1(로그인 흐름). 일부러 틀린 비밀번호를 넣어 본 첫 단계에서 나왔다.

## 수정
`client.ts`에서 **로그인 요청 자체의 401은 리다이렉트하지 않는다.** 이미 `/login`에 있을 때도
다시 보내지 않는다(불필요한 새로고침 방지).

```ts
const url: string = err.config?.url ?? '';
const isLoginRequest = url.includes('/auth/login');
if (err.response?.status === 401 && !isLoginRequest) {
  localStorage.removeItem('crack-token');
  if (window.location.pathname !== '/login') {
    window.location.href = '/login';
  }
}
```

## 확인
- 틀린 비밀번호 → `비밀번호가 올바르지 않습니다` 표시, 입력값 유지
- 맞는 비밀번호 → 정상 로그인
- 토큰이 만료·무효인 상태로 보호된 화면 진입 → 여전히 `/login`으로 보낸다 (리다이렉트 경로는 살아 있다)
