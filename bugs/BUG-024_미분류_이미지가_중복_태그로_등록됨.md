# BUG-024: 가져오기가 미분류 이미지를 같은 태그 이름으로 중복 등록

## 상태: 수정완료 (T29)
## 심각도: 낮음

## 증상
URL 가져오기(T28)로 만든 `images.md`에 인물과 매칭되지 않은 이미지가 `- 태그를_정하세요: URL` 형태로 **여러 줄 같은 이름으로** 들어간다. 태그가 중복이면 첫 항목만 인식되고 나머지는 무시된다(카탈로그 파서 규칙).

## 재현
`https://jangsue.uk/MG/web.html`과 `https://jangsue.uk/HT/FWeb.html`을 가져오면 각각 3줄이 생긴다.

## 원인
T28 명세에는 "인물과 매칭 안 되는 이미지는 장면 태그 후보로 **주석 처리**해 둔다"고 되어 있는데, 구현이 실제 항목으로 등록했다.

## 수정 (T29, 2026-09-26)
`ImportDocs.images`가 미분류 이미지를 **줄마다 따로 닫힌 주석**으로 남긴다. 태그 이름은 넣지 않는다.

```
<!-- 인물과 맞지 않는 이미지 3개입니다. 장면·배경으로 쓸 것만 아래 주석을 풀어 `- 태그: 주소 | 설명` 형식으로 고치세요. -->
<!-- 미분류 이미지 1: https://… — 쓰려면 주석을 풀고 태그 이름을 정하세요 -->
```

- 줄마다 주석이 닫히므로 한 줄만 풀어도 나머지는 그대로 주석이다.
- 태그 이름을 미리 넣지 않으니 주석을 풀 때 중복 태그가 생기지 않는다.
- 회귀 테스트: `ImportDocsTest.미분류 이미지는 줄마다 따로 주석으로 남기고 태그 이름을 넣지 않는다`.
- 이미 만들어진 두 시나리오의 파일은 오케스트레이터가 수동으로 정리했다(2026-09-26).

## 참고: 파서는 원래도 주석을 읽지 않았다
`ImageCatalogParser`는 여러 줄 주석도 지우므로(`<!--[\s\S]*?-->`), **잘못된 항목이 카탈로그로 읽힌 적은 없다.**
실제 피해는 사용자가 주석을 풀 때 같은 태그 이름 3~8줄이 생기고 첫 줄만 남는 것이었다. 그래서 심각도는 낮음이다.
